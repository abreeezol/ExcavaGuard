# 隧道监测适配器

适配器ID：`tunnel-monitoring`，初版1.0.0。保持Supervisor、报告、审计三Agent和通用Skill，由工程配置决定检索与计算。

用户新建时只选择“隧道工程”，不选择适配器或知识库。首次确认工程类别（轨道/公路/城市道路）、工法（盾构/矿山/明挖）、阶段和特殊地质。上传后按实际识别的测项提供必要参数确认。目录16本规范全部建立独立候选索引，不与基坑库混用。正常报告仅允许效力已确认且分类适用的规范；废止和效力待核资料只用于离线检查。多工法标准中的明确其他工法片段还有保守排除，不能替代具体条款适用性审查。

计算支持地表、建筑、拱顶沉降及净空收敛，统一mm，速率mm/d。时区统一Asia/Shanghai，保留原始时间，跨UTC日期按当地日期归入报告。高程下沉为初始基准减本次高程；收敛数据须已按向内为正形成累计量。**原始断面距离不能直接当累计收敛量**。输入语义不匹配时弃权，不生成可靠累计值/速率。

控制值通过“监测参数”业务表单按本次数据测项分别确认，用户无需填写内部control_metric或配置JSON；程序把这些确认转换为确定性计算所需的结构。未配置测项列为待核，不借用其他测项限值。原有扩展工程参数继续保留。

适配器资产包含：字段映射、确定性计算/规则执行、规范目录与效力状态、独立知识库清单、工程范围策略、报告与文件审计、专业评价样例及软件复跑结果。`professional-basis.json`说明公式和专业边界；没有从OCR自动生成未经核实的数值判据。

## 构建与检查

```bash
# WSL Linux环境，先激活项目虚拟环境
python -m pip install -r tools/knowledge/requirements-ocr.txt
python tools/knowledge/build_tunnel.py --workers 8
npm run tunnel:verify
npm run adapter:validate -- tunnel-monitoring
npm run adapter:evaluate -- tunnel-monitoring
npm run adapter:release -- tunnel-monitoring
```

构建脚本严格检查目录与`tunnel-sources.json`清单一致，源PDF保持只读。缓存按源文件SHA/页码保存，异常中止不会覆盖已发布库。规范候选使用中文二元词与BM25风格排序，**不是模型微调，也不是向量模型训练**。新部署需构建或复制校验后的SQLite索引；OCR仅离线运行，在线检索只需标准库SQLite，不引入Torch。

隧道只有一个在用业务入口。已有隧道工程接入同一处理实现，参数与资料兼容保留；缺少的必要分类条件首次确认后复用。历史资源仅供固化报告与测试兼容，不展示为另一项选择。详见[30号记录](../../方案与迭代note/30_工程类型统一入口与隧道参数路由.md)。

软件测评不代表真实工程验证或工程师专业认可。未覆盖应力、气体浓度、水压等测项，不得用于自动判定这些风险。
