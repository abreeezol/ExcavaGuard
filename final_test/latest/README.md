## 文件分工

| 目录 | 内容 |
| --- | --- |
| `inputs/` | 前端可上传的合成CSV、Python引擎请求JSON、另用于规范上传功能的合成文本和元数据。 |
| `snapshots/` | 周期冻结事实、对应公共规范证据及历史模型正文；供离线复现，避免依赖本地工作区外的文件；规范文件定位转为仓库相对路径，数值及每日hash不变。 |

## 数据来源和统计口径

监测数据完全人工合成，来自 `tests/standard-review-model-live.mjs` 的固定样例，不含真实工程观测。输入8条：2026-10-01至10-08，单个墙顶水平位移测点，数值依次为0、5、12、22、35、52、60、62 mm。

周报区间为2026-10-02至10-08，共7天、7条区间观测。10月1日用于保留历史基准，不计入周期统计。测试工程条件为一级、地下连续墙、开挖深度20m；仅用于软件验证。

“每日事实hash”保留在冻结快照内部；可见表格改为观测摘要与完整明细跳转。数值已归一化；宽表场景采用每日末值，不等于全部原始采样。冻结载荷无法唯一确认单位时显示“—”，不猜测补齐。

`project_standard_simulated.txt` 是额外的上传测试材料，**不是实际行业/地方标准**，请在独立测试工程使用。该合成文件未被写入本示例周报；本周报引用的是 `weekly_evidence.json` 内的公共规范候选。

正文来自之前真实模型与RAG验收的冻结结果；本次用新展示逻辑重新生成三件套并通过确定性文件审计，没有再次调用外部模型，不能将本次重导出算作一次新的真实模型语义验收。

## 如何复现

在仓库根目录，使用项目Python虚拟环境及 `pypdf`、`fonttools`、`openpyxl` 等既有依赖：

```bash
.venv/bin/python tools/test/verify-weekly-sample.py
.venv/bin/python -B 确定性计算层/pipeline/tests/test_period_reports.py
```

第一个命令检查发布文件哈希、重算冻结事实、离线重渲染报告，并核对Excel值/跳转和Markdown；临时产物在验证后清理。Excel字节可能随生成时间变化，因此重渲染比较单元格和链接，而非要求重新生成的ZIP字节完全一致。

前端测试：上传 `inputs/weekly_simulated.csv`，填写上述条件，选择周报和2026-10-08。AI模式重新运行可能生成不同正文；模板模式也能检查每日数据展示。
