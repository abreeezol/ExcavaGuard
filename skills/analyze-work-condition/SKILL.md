# 工况关联分析

## 触发条件

- 已有规则引擎输出的结构化异常事实。
- 已有带时间与空间信息的施工工况，可选附规范证据和相似案例。
- 需要形成“可能相关”的辅助解释，而非确定性安全结论。

## 输入

- `judgments`：阈值 Skill 输出的测点、时间、监测项、观测值和超限事实。
- `work_conditions`：施工事件列表，至少含事件时间、位置、类型和描述。
- `standard_evidence`：可选规范证据，必须包含可追踪 ID。
- `similar_cases`：可选相似案例，必须包含相似度和差异限制。
- `time_window`、`spatial_window`：项目配置的时间窗与空间窗，不得由模型臆造。

## 输出

成功时返回逐异常点分析：

- `point_id`、`metric`、`observed_fact`；
- `candidate_causes`：候选工况、时间/空间/方向/量级匹配结果；
- `evidence_ids`：使用的规范或案例证据；
- `confidence`：受约束的可信等级及理由；
- `limitations`：缺失信息和差异项；
- `trace`：筛选与比较过程。

## 执行流程

1. 仅选取规则引擎确认的异常事实，不重新计算或修改超限状态。
2. 按时间窗和空间窗筛选候选施工事件。
3. 比较异常方向、量级、施工阶段及已知影响机制。
4. 使用规范证据说明适用边界，使用案例证据补充经验参照。
5. 输出候选原因、支持证据、反证或差异项与可信等级。
6. 若证据不足，返回统一弃权结论“信息不足，建议人工复核”。

## 失败与弃权边界

- 缺少异常事实、工况记录或有效时间/空间配置：以 `ATTRIBUTION_INSUFFICIENT` 弃权。
- 证据无来源、相互冲突或无法覆盖当前工程条件：弃权并列出冲突。
- 无候选工况能解释异常，或只有低相似案例：弃权，不强行归因。
- 不使用时间先后替代因果证明，不修改任何计算值，不发布预警或处置指令。
