# 日报一致性校验

## 触发条件

- `render-daily-report` 已生成日报草稿。
- 报告即将导出、提交人工审核或重新渲染。
- 不用于修正源数据、重新计算阈值或签发报告。

## 输入

- `report_draft`：待校验日报草稿。
- `fact_bindings`：报告字段到结构化事实的映射。
- `judgments`：规则引擎原始输出。
- `citations`：报告引用及证据 ID。
- `template_requirements`：模板必填字段、章节和版本要求。
- `prohibited_phrases`：禁止出现的自动预警、自动签发或确定性归因措辞。

## 输出

校验通过时返回：

- `valid=true`；
- `checks`：数字、超限状态、引用、适用性、必填字段、模板和措辞检查结果；
- `trace`：逐项核验依据。

校验失败时仅返回：

- `valid=false`；
- `errors`：包含字段位置、期望值、实际值和错误码的清单；
- 不返回可视为正式报告的成品。

## 执行流程

1. 逐字段比对报告数字与结构化事实。
2. 比对超限状态、规则 ID、单位、时间和测点。
3. 核验每条引用存在、可追踪且适用于对应监测项。
4. 检查模板版本、章节和必填字段完整性。
5. 检查是否出现未经授权的预警、签发或过度归因措辞。
6. 汇总全部问题；仅当关键检查全部通过时允许进入人工复核与导出环节。

## 失败与弃权边界

- 任一数字或超限状态不一致：以 `VALIDATION_FAILED` 拒绝输出正式报告。
- 引用不存在、不可追踪、适用性不明或相互冲突：校验失败。
- 必填字段缺失、模板版本未知或出现禁止措辞：校验失败。
- 校验器自身异常：安全弃权并保留错误清单。
- 不自动修改事实以迁就报告，不替代工程师审核、签字、预警发布或最终签发。
