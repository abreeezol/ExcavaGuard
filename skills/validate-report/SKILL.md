# 日报一致性校验

## 触发条件

- `render-daily-report` 已生成日报草稿。
- 报告即将导出、提交人工审核或重新渲染。
- 不用于修正源数据、重新计算阈值或签发报告。

## 输入

- `report_draft`：待校验日报草稿。
- `fact_bindings`：报告字段到结构化事实的映射。
- `artifacts`：待校验的日报 Excel、封面 Markdown、附表及清单 Markdown 清单。
- `artifact_bindings`：Excel 单元格到冻结载荷事实字段的映射。
- `judgments`：规则引擎原始输出。
- `citations`：报告引用及证据 ID。
- `template_requirements`：模板必填字段、章节和版本要求。
- `prohibited_phrases`：禁止出现的自动预警、自动签发或确定性归因措辞。

## 输出

校验通过时返回：

- `valid=true`；
- `checks`：数字、超限状态、引用、适用性、必填字段、模板和措辞检查结果；
- `trace`：逐项核验依据。

校验失败时仅返回：

- `valid=false`；
- `errors`：包含字段位置、期望值、实际值和错误码的清单；
- 不返回可视为正式报告的成品。

## 执行流程

1. 逐字段比对报告数字与结构化事实。
2. 比对超限状态、规则 ID、单位、时间和测点。
3. 核验每条引用存在、可追踪且适用于对应监测项。
4. 检查模板版本、章节和必填字段完整性。
5. 检查是否出现未经授权的预警、签发或过度归因措辞。
6. 核对三件套文件集合、受控路径、SHA-256 和字节数。
7. 逐单元格核对 Excel 表头、事实值、风险状态、来源说明与
   `artifact_bindings`；核对两份 Markdown 与同一结构化草稿逐字一致。
8. 检查只生成实际出现的附表 A～F；缺巡视记录时表 G 必须省略，且不得出现
   “巡视正常”等无依据表述。
9. 检查附表逐测点备注中的规范编号和条文来自冻结 `evidence` /
   `effective_standard`，并检查附表 C～F 前两列为绑定事实的监测日期与孔号(点号)。
10. 汇总全部问题；仅当关键检查全部通过时允许进入人工复核环节。

## 当前实现

- 服务端 runner：`src/server/skills/validate-report/runner.ts`。
- 确定性校验器：`scripts/validate_report.py`。
- 校验器使用当前引擎、证据与分析快照重新渲染期望草稿，核对报告内容哈希、
  事实路径和值、SHA-256 绑定、证据 ID、必填章节、草稿标记和责任措辞；同时读取
  三件套文件，核对文件哈希、Excel 单元格绑定和 Markdown 对应关系。
- AI 日报模式下，确定性校验通过后还会由审计 Agent 发起独立 LLM 语义审查，
  检查证据支持、责任边界、虚构工况和越权建议；语义问题合并进同一
  `audit_result`，仍不得修改源事实。
- `skills/deep-pit-monitoring-report/scripts/validate_report.py` 保留为原型与 Markdown
  数值自检资产；服务端使用本目录的结构化校验协议，不解析自然语言来修改事实。

## 失败与弃权边界

- 任一数字或超限状态不一致：以 `VALIDATION_FAILED` 拒绝输出正式报告。
- 引用不存在、不可追踪、适用性不明或相互冲突：校验失败。
- 必填字段缺失、模板版本未知或出现禁止措辞：校验失败。
- 三件套缺件、路径越界、文件哈希不一致、Excel 单元格或 Markdown 被修改：校验失败。
- 校验器自身异常：安全弃权并保留错误清单。
- 不自动修改事实以迁就报告，不替代工程师审核、签字、预警发布或最终签发。
