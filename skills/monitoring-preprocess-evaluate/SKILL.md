# 监测数据预处理与预警评价（表 E / 表 F + RAG 证据）

## 触发条件

- 输入为宽表监测 CSV：首列为时间（精确到分钟），其余各列为不同测点的原始观测值
  （列名形如 `地下水位-SW-01-原始值(mm)`、`地表竖向位移-DBC-01-原始值(mm)`、
  `分层竖向位移-FC-01-原始值(mm)`、`坑底隆起-KB-01-原始值(mm)`、
  `裂缝-LF-01-长度-原始值(mm)`、`裂缝-LF-01-宽度-原始值(mm)`）。
- 需要把原始值预处理为 GB 50497-2019 表 E / 表 F 要求的日报快照格式
  （含累计变化量、本次变化量、变化速率、报警值、控制值、等级）。
- 需要为预警结论附规范名称、版本、条文号与来源定位（来自 RAG 标准库）。
- 不用于解析非监测类文件、选择工程报警值或替代工程师判断。

## 输入

- `csv_path`：原始监测 CSV 路径（宽表）。**必填**。
- `foundation`：可选，`深基础` → 安全等级一级；`浅基础` → 安全等级三级。
  缺省时从文件名推断（`深基础`/`浅基础`）。
- `interval_minutes`：采样间隔（分钟），默认 `5`。
- `rag_enabled`：是否启用 RAG 证据层，默认 `true`；
  设为 `false` 时仅做确定性预处理与阈值判定。
- `output_dir`：输出目录，默认与输入 CSV 同目录。

## 输出

成功时在 `output_dir` 写出（格式严格对齐真实基坑监测日报
《建筑基坑工程监测技术标准》GB 50497-2019 附表 E_地下水位等监测日报表 / 附表 F_裂缝监测日报表）：

- `附表E_格式化.csv` 与 `附表E_格式化.xlsx`：地下水位等监测日报表。列：
  `初始高程, 本次高程, 上次高程, 本次变化, 累计变化, 变化速率, 日内峰值速率(mm/d), 编号, 点号, 备注`。
  每测点按监测日展开为多行（日报时间序列）；`备注` 列集中承载预警信息
  （预警等级 / 报警值 / 控制值 / 占报警值% / 超报警值 / 超控制值 / 触发原因 /
  速率增强(8.0.3-3连续超70% / 8.0.9突变 / 日内峰值速率) / 规范依据(RAG)）。
- `附表F_格式化.csv` 与 `附表F_格式化.xlsx`：裂缝监测日报表。列：
  `长度(mm), 宽度(mm), 本次测试值, 单次变化, 累计变化, 变化速率, 日内峰值速率(mm/d), 点号, 形态, 备注`。
  裂缝宽度为主预警项；长度列若无可不填（"—"）。
- `evaluation.json`：结构化判定载荷，含逐测点的基线/末值/本次变化/速率/累计/
  生效限值及其来源（`standard` + `clause`）/等级/弃权码，以及 RAG 证据与 trace；
  另含 `summary.level_counts` 与 `analysis`（附表 E/F 的「简要分析及判断性结论」文本）。
- xlsx 另含标题块（工程名称、报表编号、天气、观测/计算/校核者、仪器、监测时间）、
  页脚（工况描述、简要分析、负责人、页码）与「简要分析及判断性结论」段落，
  直接可作为日报附表使用（需 openpyxl；缺失时仅产出 CSV，不阻断）。

等级取值（对齐真实日报三级体系）：`正常` / `黄色(需关注)` / `红色(报警)` / `未判定`
（未判定=弃权，不是安全）。

## 确定性计算与判定（阶段 A，仅标准库即可运行）

- 按自然日重采样（**分析每日内变化**）：原始为 5 分钟时序，不再仅取每日末次读数，
  而是对每一自然日利用「日内首末读数及其实际时间间隔」计算日内变化与速率：
  - 本次高程 = 当日最后一次读数；上次高程 = 当日第一次读数。
  - 本次变化量 = 当日末次 − 当日首次（**日内窗口变化**，非跨日端点差；首日亦为日内真实变动，不为 0）。
  - 累计变化量 = 当日末次 − 基线（首值）。
  - 变化速率(mm/d) = 本次变化量 ÷ 当日首末读数间隔（天），即**按当日实际时长折算的日内平均速率**
    （保留用户要求的"日内变化"口径，用于附表「变化速率」列）。
- **逐期速率序列（A）**：在日平均之外，另对相邻读数对计算逐期速率
  `r_i = (v_i − v_{i-1}) ÷ Δt_i（天）`（单位 mm/d，即规范附录E/F「变化速率(mm/d)」的逐期展开）。
  该序列是下列两条规范速率判据的数据基础，也用于计算「日内峰值速率」。
- **速率预警的规范口径**（已与 RAG 标准库及 `thresholds_gb50497_2019.json` 核对）：
  预警速率 = **表 8.0.4 / 8.0.5 的"变化速率"列（mm/d）**，即监测周期速率，非日平均；
  8.0.3 明确"累计变化预警值 **和** 变化速率预警值"双控。
- **三级 + 速率增强判定**（对齐真实日报，并补齐规范速率条款）：
  - `红色(报警)`：
    ① 累计 ≥ 报警值（表 8.0.4/8.0.5 累计）；或
    ② 速率 ≥ 报警速率（规定值，mm/d）；或
    ③ **连续 3 期逐期速率 ≥ 0.7 × 报警速率**（GB 50497-2019 **8.0.3-3**）；或
    ④ **位移突然明显增大**（GB 50497-2019 **8.0.9-1** 危险报警：单期速率 ≥ 0.7×报警速率
       且 ≥ 3 × 该点逐期速率中位数，定义为"明显突变"）。
  - `黄色(需关注)`：累计 ≥ 0.7 × 报警值，或速率 ≥ 0.7 × 报警速率（接近报警的前期关注）。
  - `正常`：其余。
  - `未判定`：无适用阈值（如分层竖向位移、裂缝长度）或安全等级无法解析。
  - 控制值为 GB 强制上限，不在等级判定中另立一级，仅在「备注」提示「超控制值：是/否」。
  - 注：8.0.3-3 的"连续3期≥70%"在持续偏高时直接判红，与日报"黄色"是不同层级；
    黄色仅用于"1–2 期短暂触及 70% 速率"的过渡关注，不替代 8.0.3-3。
- **日内峰值速率（D，辅助列，非规范强制字段）**：每一自然日内相邻读数最大 |r_i|（mm/d），
  写入附表「日内峰值速率(mm/d)」列。日平均速率会掩盖日内突变，该列用于凸显瞬时突跳
  （如 SW 点一次 100mm/5min 突跳的日平均仅约 100 mm/d，而日内峰值达 28800 mm/d）。
- 无适用规则或安全等级无法解析：以 `未判定` 弃权，只报告原始监测值，不臆造阈值、不判为安全。

## RAG 证据层（阶段 B，需 chromadb）

- 对每个有阈值的监测项，检索 `data/chroma_db/` 中的 `jikeng_norms` 集合
  （标准库，由 `source/build_kb.py` 训练），取该监测项 `evidence.clause` 对应条文作为依据。
- 检索结果须携带稳定来源（`source` / `clause` / `category` / `score`），不改写规则事实。
- 规范判据优先级高于案例经验；本项目当前 RAG 仅含标准库，无独立案例库集合，
  案例检索在未建集合时按约束返回「信息不足」。
- 依赖缺失或集合不可用时优雅降级：确定性层照常完成，RAG 层返回
  `EVIDENCE_NOT_FOUND`（原因 `RAG_DEPENDENCY_MISSING` / `RAG_COLLECTION_MISSING`），
  不阻断主流程、不伪造条文。

## 执行流程

1. 读宽表，用 `utf-8-sig` 解析，识别时间列与测点列。
2. 按列名前缀映射 metric_key 与表类型，提取点号。
3. 逐测点按自然日重采样为日报时间序列。
4. 载入默认规范库阈值，按 `metric_key` + 安全等级选适用规则，取报警值/控制值。
5. 三级判定；无规则项标记 `未判定`。
6. （启用时）逐监测项检索 RAG 标准库，附规范条文证据。
7. 生成「备注」文本（预警等级/报警值/控制值/占报警值%/超报警值/超控制值/规范依据）。
8. 写出附表 E / F 的 CSV 与 xlsx（含标题块、页脚、简要分析结论）与 `evaluation.json`。

## 失败与弃权边界

- 文件不存在 / 非 CSV / 无数据：以 `INVALID_INPUT` 弃权。
- 时间列缺失或无法解析：以 `DATA_QUALITY` 弃权。
- 安全等级无法解析（文件名与参数均无）：以 `MISSING_SAFETY_LEVEL` 弃权，
  该批点不判级（标记未知）。
- 监测项无适用阈值：以 `UNKNOWN_METRIC` 弃权，仅报值。
- chromadb 未安装或集合不存在：RAG 层 `EVIDENCE_NOT_FOUND`，确定性层不受影响。
- 不从自然语言推断阈值，不伪造条文、版本、页码或来源，
  不发布预警，不形成正式工程结论。
- 阈值用于真实工程前必须由基坑工程设计方确认（GB 50497-2019 第 8.0.1 条）。
