## 1. Git 推送 / 核验

### 1.1 SOCKS5 10808 替代弃用 HTTP 7361
- **现象**：`git push` / `git ls-remote` 超时或 502。
- **根因**：旧 HTTP 代理端口已弃用。
- **解决**：改用 SOCKS5 端口 10808。
- **本 Skill**：不执行任何 git 操作，**不适用**。
- **预防**：推送类脚本单独维护代理配置，不写进数据处理 Skill。

### 1.2 `git ls-tree -z` 修中文路径漏数误判
- **现象**：中文文件名被转义，`git ls-tree` 统计文件数偏少。
- **根因**：默认 `core.quotepath` 会把非 ASCII 路径转义。
- **解决**：`git ls-tree -z` 配合 `core.quotepath=false`。
- **本 Skill**：**不适用**。但同类风险在本 Skill 中的表现是**中文列名/点号**——
  已用「归一化后按别名匹配」而非按位置取值来规避（见 §5.2）。

## 2. RAG 依赖

### 2.1 chromadb 安装（`only-binary` + 清华镜像）
- **现象**：`pip install chromadb` 编译失败或超时。
- **解决**：`--only-binary=:all:` + 清华镜像源。
- **本 Skill**：**不安装 chromadb**。`assets/rag_hits.json` 为内置命中缓存，
  分发后对方**无需 torch / chromadb** 也能得到带 RAG 命中的 I/J 两列。
- **预防**：把「重依赖」与「结果」解耦，结果缓存入库。

### 2.2 `CODEBUDDY_SAFE_DELETE_ENABLED=0`
- **现象**：沙箱 safe-delete 守卫拦截批量删除。
- **本 Skill**：**不删任何文件**（`--split` 只新增文件，从不删除），**不适用**。

### 2.3 进度条污染 stdout ✅ 已修
- **现象**：调用方按 stdout 解析结果时，混入 `Loading weights: 100%|...` 等进度条。
- **根因**：`chromadb` / `sentence-transformers` / `transformers` 默认把进度条写 stdout。
- **解决**（`scripts/rag_lookup.py`）：
  1. 设 `TQDM_DISABLE=1`、`HF_HUB_DISABLE_PROGRESS_BARS=1`、`TRANSFORMERS_NO_ADVISORY_WARNINGS=1`；
  2. 模型加载与检索整段用 `contextlib.redirect_stdout(sys.stderr)` 包裹；
  3. 本脚本自身的状态输出也一律走 **stderr**，结果只写 `--out` 指定的文件。
- **验证**：`rag_lookup.py ... >out.txt 2>err.txt` → `out.txt` **为空**，进度条只在 `err.txt`。
- **预防**：约定「stdout 只放结果，日志一律 stderr」。

## 3. 计算口径（最易踩坑）

### 3.1 只取末次读数掩盖日内变化 ✅ 已修
- **现象**：日报只填当日最后一次观测值，日内出现的峰值/突变被抹掉。
- **根因**：按日聚合时直接取末条记录。
- **解决**（`fill_summary_table.aggregate_daily` + `intraday_flags`）：
  - 聚合时**同时记录当日极值**（`day_min` / `day_max` / `day_count`）；
  - 「汇总」页新增 **「二·补充、日内极值提示」**：当 `day_max − day_min > 2 × |本期变化量|`
    时列出该测点，提示「日报口径的本次变化量可能低估日内实际波动，须人工复核原始时序」。
- **预防**：任何「按日聚合」都必须同时保留日内极值，不能只留末次。

### 3.2 日平均速率掩盖突变 ✅ 已补
- **现象**：用「本期变化 ÷ 天数」当速率，掩盖突变；规范里两条量化判据被漏掉。
- **根因**：只实现「累计量」判据，未实现 GB 50497-2019 第 8.0.3 条与第 8.0.9-1 条。
- **解决**（新增 `scripts/rate_rules.py`，在 `cd` / `verdict` / `af` 三种形态统一生效）：

  | 判据 | 依据 | 触发条件 | 等级 |
  |---|---|---|---|
  | 连续超 70% | **第 8.0.3 条** / 表 8.0.4 注 | 变化速率**连续 3 次** ≥ 速率限值 × 70% | 至少 **橙色预警** |
  | 突然明显增大 | **第 8.0.9-1 条**（强制性条文） | 本次变化量 ≥ **3 倍**前 3 期变化量**中位数** | **红色预警** |

  - 期次序列由 `_tail_of()` 统一派生（输入自带变化量/速率时以输入为准）；
  - **只升不降**，理由与依据条款写入备注；
  - **亚日级序列主动弃权**：采样间隔 < 1 天时（如 5 分钟级）序列由噪声主导，
    倍数判据会产生大量假突变 → 返回空结果并注明原因；
  - **期次不连续（序列含 `None`）拒绝判「连续」/「突变」**，避免跨缺口误判；
  - 「突变倍数」规范**未定量**，默认 3.0，属**工程经验判据**，须由项目专项方案确认，
    可用 `--sudden-factor 0` 关闭；`--rate-rules off` 可整条关闭。
- **验证**：构造 `地下水位` 4 期数据（速率 400/400/400/2000，限值 500）：
  - 第 2 期 → **橙色(预警)**，备注注明「连续 3 次达到速率限值的 70% 以上（依据第 8.0.3 条）」；
  - 第 3 期 → **红色(报警)**，两条判据同时命中并各自注明依据条款；
  - `--rate-rules off` → 两条判据均不生效。
- **预防**：判据库里的 `rate_alarm_policy` / `danger_alarm_conditions` 必须**逐条落地**，
  不能只挑「累计值」实现。

### 3.3 三级预警体系与控制值处理 ⚠️ 口径差异（已声明）
- **同事项目**：三级（正常 / 需关注 / 报警）。
- **本 Skill**：
  - `verdict` 形态：**正常 / 黄色 / 橙色 / 红色 / 未知**（未知 = 弃权）；
  - `af` 形态：**正常 / 黄色(需关注) / 橙色(预警) / 红色(报警) / 未判定**，
    与参考文档 `监测日报_附表AF_RAG.xlsx` 的「备注」写法一致。
- **报警值 / 控制值取法**：判据库区间**下限 = 报警值、上限 = 控制值**；
  内力/轴力类为设计值占比，未提供 `--design` 时以 `60%f2` 文本展示且等级为 `未知`。
- **结论**：属**跨项目口径差异**，非缺陷；已在 `references/04`、`references/05` 声明。
  若需统一为三级，需项目方确认后再改。

## 5. 运行 / 调试

### 5.1 相对路径基准错 ✅ 已核 + 加固
- **本 Skill 核查**：
  - `skill_root` 一律用 `Path(__file__).resolve().parent.parent`（绝对路径），
    内置判据库、RAG 缓存、示例资产全部基于它定位，**与 CWD 无关**；
  - `--input` / `--output` 按用户给定路径处理（标准 CLI 语义）；
  - 输出完成时打印**绝对路径**（`out.resolve()`），避免「以为写到了别处」。

### 5.2 沙箱拦截复合命令 / 内联 `python -c`
- **现象**：沙箱对复合命令、内联 `python -c` 有额外拦截。
- **本 Skill**：属**运行环境**问题，非 Skill 缺陷。脚本本身是单文件 CLI，
  不依赖复合命令；文档中的命令示例都是单条 `python scripts/xxx.py ...`。
- **预防**：交付时优先给「单条命令」而非「`&&` 串联」。

### 5.3 期次退化（span_days = 0）✅ 已修
- **现象**：只有一期数据、或相邻两期时间戳相同时，`变化 ÷ 0 天` 崩溃或产生 `inf`。
- **本 Skill 除零审计**（逐处核对）：

  | 位置 | 表达式 | 保护 |
  |---|---|---|
  | `_tail_of` | `ch / dt` | `if dt else None` |
  | `build_interval_rows` | `change / dt` | `if (change is not None and dt)` |
  | `build_appendix_rows` | `change / dt` | `if dt else None` |
  | `appendix_table.resolve_row` | `abs(cum) / warn_abs` | `try/except ZeroDivisionError` + `if warn_abs` |
  | `verdict_table` 说明页 | `1440 / iv` | **本轮修复**：过滤 `iv <= 0` |
  | `rate_rules` | `warn_rate <= 0` 直接返回 | `if float(warn_rate) <= 0` |

### 5.4 字段错位（按位置 zip）✅ 已修
- **现象**：`_eval_point` 之类按位置取字段，列序一变就串行。
- **本 Skill 核查与修复**：
  - `appendix_table.write_appendix_sheet` 原来用 `zip(rows, infos)` 平行列表 →
    **改为把判定信息写回行内**（`row["_info"]`），`_analysis_lines` 也改读 `row["_info"]`；
  - `fill_summary_table` 的派生一律用**关键字**（`dict(r, prev=…, change=…)`），不按位置；
  - **新增自查发现（见 §7-A）**：等级用词跨模块不一致导致比较静默失效，已修。

## 7. 本 Skill 自查新发现的缺陷（同事手册未覆盖）

### A. 等级用词跨模块不一致 → 升级静默失效 ✅ 已修
- **现象**：`rate_rules` 判定为「橙色预警」，但结果仍显示「黄色」，**没有任何报错**。
- **根因**：`verdict_table` 的等级用词是 `黄色 / 橙色 / 红色`，
  `rate_rules` 用 `黄色预警 / 橙色预警 / 红色预警`；
  比较时 `list.index()` 抛 `ValueError` 被 `except` 吞掉，直接返回原值。
- **解决**：`rate_rules.bump_level()` 改为**先归一再用序比较**
  （`level_rank()` 覆盖 `黄色 / 黄色预警 / 黄色(需关注) / 需关注` 等全部变体）。
- **验证**：`黄色 + 橙色预警 → 橙色预警`、`红色 + 橙色预警 → 红色`（只升不降）、
  `未知 + 橙色预警 → 橙色预警`。
- **预防**：跨模块传递「等级」这类**枚举**时，先统一词表或统一用 rank；
  `except ValueError` 不能静默返回原值，至少要留痕。

### B. 多 sheet 列名不同时只用首行建映射 ✅ 已修
- **现象**：同一工作簿不同 sheet 用不同列名（「点号」与「孔号(点号)」），
  部分 sheet 的字段取不到值。
- **根因**：`build_column_map()` 只用**第一行**的列名建立映射表。
- **解决**：改为**逐行取值**（`_row_getter()` 用该行自身的列名做归一化查找）。

### C. 非记录表 sheet / 页脚行污染待复核 ✅ 已修
- **现象**：附录表式的「工况描述 / 简要分析 / 第 页 共 页」以及
  `超限测点清单`、文字说明页，全部变成「测点号缺失」的待复核条目（一次 200+ 条）。
- **解决**：`_is_non_data_sheet()` 整表跳过（并在读取报告中列出）；
  `_is_footer_row()` 跳过页脚行；「汇总」页的待复核**按原因合并计数**，不再逐条刷屏。
