# 日报交付前自检清单

逐条核对，任一条不通过则回到对应步骤重做，不得直接交付。

## 0. 先跑自动自检

```bash
python scripts/validate_report.py --report 监测日报_YYYYMMDD.md --result result.json --config thresholds.json
```

- [ ] "表格数值一致性"显示**通过**；若有问题项，逐条修到通过为止。
- [ ] "全文数值+单位人工确认清单"为空，或已逐条确认属工况描述等正常例外。

## A. 数值正确性

- [ ] 报告中每个数值都能在 `compute_metrics.py` 输出的 JSON 中找到同值字段，无一例外。
- [ ] 没有出现对话中口算、估算或模型自行推导的数值。
- [ ] 累计量、本次变化量、变化速率三者相互自洽（变化量 ÷ 间隔天数 ≈ 速率）。
- [ ] 缺失值显示为"—"或明确标注，没有被 0、空字符串或插值替代。

## B. 依据完整性

- [ ] 每条判定都带依据来源（专项方案条款 / 标准条款编号 / 项目规则文件名），来源为空的一律转待复核。
- [ ] 阈值来自项目已审批文件；没有出现"经验值""通常按""参考类似工程"补出的阈值。
- [ ] 引用的标准条款与现行版本一致（需要原文时用官方渠道核对，不凭记忆写条款号）。

## C. 表式与字段完整性（GB 50497-2019 附录 A~G）

- [ ] 每张表的标题、主表列名、列顺序、单位与 `references/appendix_forms.md` 完全一致，未增删列、未改列名、未调换单位；汇总表 xlsx 的三处格式修改（预警等级列、表 B 点号列、集中列示）已在"汇总"页说明中列明。
- [ ] 测项归表正确：位移类→表 A；测斜→表 B；内力/土压力/孔隙水压力→表 C；轴力→表 D；水位/地表与分层竖向位移/坑底隆起→表 E；裂缝→表 F；巡视检查→表 G。
- [ ] 每张表都有固定表头（第（ ）次、工程名称/报表编号/天气、观测者/计算者/校核者、仪器型号/仪器编号/检定有效期、本次与上次监测时间）与表尾（工程负责人、监测单位、第 页 共 页）。
- [ ] 表内"工况描述""简要分析及判断性结论"两栏均有内容或明确占位，未留空白单元格；引用原表已载内容时已标注"供审核参考"。
- [ ] 表头缺失字段留 `＿＿＿＿`、数据源没有的字段留 `—`，**未编造**观测者、仪器编号、检定有效期、高程、组号、深度。
- [ ] 附录表式之外的汇总信息只出现在"附表"章节或汇总表"汇总"页，且已注明性质。
- [ ] 编制/审核/签发栏存在且**留空待签**，未代填人名、未写"已审核"。

## C2. 附录表式 Excel 输入（形态 ①）专项

- [ ] 表内一致性校核全部复核：高程差 vs 变化量、测值差 vs 本次变化，不一致项已逐条标注待复核，未改数。
- [ ] 阈值单位与附录表列单位一致（表 E 变化量栏为 mm；表 C 为 kPa；表 D 为 kN）。
- [ ] 原表工况/分析文字仅作参考带出，系统分析结论以 `--analysis` 或【待填写】占位为准。
- [ ] 表 G 巡视检查结果来自巡视记录输入，未由系统代填或推断。

## D. 追溯与保留判断

- [ ] 任一结论都能反向查到对应的原始记录、计算结果与适用条款。
- [ ] 超限测点、数据质量问题、待复核事项已集中标识，便于优先核查。
- [ ] 数据缺失、依据不明、案例不足处写明"尚不能判断，需补充：XXX"，未生成确定性原因解释。
- [ ] 工况解释只作为补充，**未**用来消除或弱化超限标识。

## E. 边界声明

- [ ] 报告含声明段：辅助材料定位、红色预警须人工确认、不替代正式监测报告、不涉及现场采集。
- [ ] 未出现"建议立即停工""预警已发布"等越过责任流程的表述（系统只提示，不发布）。

## F. 一致性

- [ ] 结论与数据表一致：超限测点没被写成"正常"，正常测点没被写成异常。
- [ ] 同一测点在数据表、超限清单、分析意见中的等级与数值一致。
