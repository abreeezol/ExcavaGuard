# 阈值判定

## 触发条件

- 输入数据已完成单位、方向、时间和字段标准化（阶段一输出）。
- 需要按现行规范条文计算累计值、本次变化量、日变化速率及风险等级。
- 不用于检索案例、选择工程报警值或替代工程师判断。

## 输入

- `records`：非空标准化记录列表。
- `context`：工程条件（安全等级、支护形式、开挖深度 H、设计值、底板浇筑日、逐测点条件）。
- `standards`：可选。缺省时使用**默认规范库**（`standards/default/`，
  取自 `基坑智守项目相关规范`，视为覆盖大多数情况的通用规范）；
  用户可上传地方规程 / 项目专项方案覆盖，**未上传时不作特殊处理**。

阈值来源规则：

- 判据必须来自**现行规范条文**，每条规则必须携带
  `evidence.standard`（规范名称）、`evidence.clause`（条文号）；
- 规范给出的区间值按 `selection_policy.range_resolution` 解析为确定值（默认取下限，偏安全）；
- 累计值取 `min(绝对量限值, %H 限值)`，`limit_mm = pct[%] × H[m] × 10`；
- 速率：达到规定值，或连续 3 次超过该值的 70%；
- 底板浇筑完成后，位移速率限值 × 0.7；
- 危险报警条件见 GB 50497-2019 第 8.0.9 条（强制性条文）。

## 输出

- `judgments`：逐测点的观测值、累计值、本次变化量、变化速率、趋势斜率、
  生效限值及其来源（`origin` = `default_library` / `user_uploaded`、规范名称、条文号）、
  利用率、风险等级、弃权码、数据来源标识；
- `risk_level`：`正常` / `关注` / `预警` / `报警` / `危险报警` / `未知`；
- `abstain`：弃权码（输入不足、无适用判据、缺设计值、数据质量阻塞等）；
- `trace`：每条记录的确定性计算过程、公式与规则标识。

## 执行流程

1. 校验记录列表与工程条件。
2. 按监测项 + 安全等级 + 支护形式（+ 管线类型 / 道路类型 / 裂缝状态）匹配适用规则。
3. 解析生效限值，记录每个字段的来源。
4. 计算累计值与本次变化量，按观测间隔计算日变化速率，按历史序列计算最小二乘趋势斜率。
5. 逐项计算利用率并分级，多项判据同时存在时取最高等级。
6. 命中 GB 50497-2019 第 8.0.9 条危险报警条件时直接判为危险报警。
7. 输出结构化判定结果，附生效规范来源与条文出处。

## 失败与弃权边界

- `records` 或 `context` 类型、内容无效：以 `INVALID_INPUT` 弃权。
- 规范库中不存在该监测项：以 `UNKNOWN_METRIC` 弃权。
- 当前安全等级 / 支护形式组合下无适用规则：以 `NO_APPLICABLE_RULE` 弃权。
- 需按设计值校核但未提供设计值：以 `MISSING_DESIGN_VALUE` 弃权。
- 高严重度数据质量问题（孤立尖峰粗差、非数值、日期不可解析、单位不可识别、传感器漂移）：
  以 `DATA_QUALITY_BLOCKED` 弃权，该期不参与判定并转人工复核。
- 不从自然语言推断阈值，不伪造条文，不发布预警，不形成正式工程结论。
- 规范条文阈值用于真实工程前必须由基坑工程设计方确认（GB 50497-2019 第 8.0.1 条）。
