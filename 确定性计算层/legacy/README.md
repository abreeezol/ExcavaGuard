# legacy · 已废弃实现

## thresholds_v1_阶段语义废弃

**状态：已废弃，不再作为流程入口。**

### 废弃原因

该目录按「阈值来源分阶段」的语义组织：把阈值划分为
`阶段1 通用默认 → 阶段2 导入标准 → 阶段3 项目专项`，
即阈值本身从通用向专项递进。

这一语义与项目最终确认的阶段划分**不一致**。项目确认的「第一阶段→第二阶段→第三阶段」指的是：

| 阶段 | 含义 |
|---|---|
| 阶段一 | **数据准备** —— 用户上传的现有数据与模拟数据统一作为风险识别参数的输入依据 |
| 阶段二 | **确定性计算** —— 累计值、本次变化量、变化速率、趋势斜率 |
| 阶段三 | **规范比对** —— 将计算结果与规范判据比对，识别风险并分级 |

三个阶段是**流程上的先后关系**，不是方案的递进关系。

### 替代实现

- `pipeline/stage1_data_preparation/` —— 阶段一
- `pipeline/stage2_deterministic_calc/` —— 阶段二
- `pipeline/stage3_standard_comparison/` —— 阶段三
- `standards/default/` —— 默认规范库（取自 `基坑智守项目相关规范`）
- `standards/user_uploaded/` —— 用户上传规范目录

阈值不再按「来源阶段」分层，而是按「规范来源」区分：
`default_library`（默认规范库）与 `user_uploaded`（用户上传规范），
后者按字段覆盖前者，未覆盖字段继承默认库。

### 保留原因

`thresholds.generic_default.json` 是 GB 50497-2019 表 8.0.4 / 表 8.0.5 的条文级摘录，
已整体迁移为 `standards/default/thresholds_gb50497_2019.json`。
本目录仅作历史留档，其 57 项回归测试仍可通过（`python -B tests/test_threshold_loader.py`），
用于核对迁移前后数值一致。

### 不要做的事

- 不要再新增依赖 `threshold_loader.py` 的调用方；
- 不要在新增文档中引用「阶段1/2/3 阈值」的说法；
- 不要按「通用方案进阶到专项方案」描述本系统。
