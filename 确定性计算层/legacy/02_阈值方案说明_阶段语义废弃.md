## 二、三阶段优先级规则

### 2.1 阶段定义

```
阶段1  generic_default    通用默认阈值（内置 GB 50497-2019）     ← 基础，始终存在，优先级最低
   ↓  被后一阶段覆盖
阶段2  imported_standard  导入标准 / 地方规程阈值               ← 覆盖阶段1
   ↓  被后一阶段覆盖
阶段3  project_specific   项目经审批专项方案 / 人工审定阈值      ← 覆盖阶段2，优先级最高
```

> **关于"第一阶段→第二阶段→第三阶段"的说明**
> 我将其理解为**阈值来源的优先级阶梯**（通用默认 → 导入标准 → 专项方案），
> 这与《项目申请书》中"国家标准、地方规程和项目经审批专项方案"的三级结构一致，
> 也满足"后一阶段覆盖前一阶段"。
> 前一版文档《确定性计算层_监测参数清单与规范依据》第七节的开发阶段划分
> （模拟数据生成 → 确定性计算 → 问题识别与风险分级）在语义上同样收敛为
> **"默认值 → 计算期加载值 → 判定期专项值"** 的递进关系，因此两种读法在实现上一致。
> 若你指的是其他映射，只需改 `ThresholdConfig` 的 `STAGE_*` 常量与导入目录即可，
> 合并逻辑无需改动。

### 2.2 覆盖规则（精确定义）

| 规则 | 说明 |
|---|---|
| **覆盖粒度** | `metric_key` + `rule_id` + **字段名** |
| **只覆盖显式字段** | 导入文件中出现的字段覆盖上一阶段；**未出现的字段继承上一阶段**，不会出现"覆盖即清空" |
| **显式置空** | 字段写 `null` 表示显式置空（如 `cumulative_mm: null` 表示该项不适用） |
| **同阶段多文件** | 按文件名排序依次合并，后者覆盖前者 |
| **规则命中** | 按 `safety_level` → `support_type` → `pipeline_type`/`road_type`/`crack_state` 逐级过滤；`any`/省略 表示通配 |
| **多规则命中** | 取"生效阶段最高、条件最具体"的一条 |
| **阶段来源追溯** | 每个字段记录其最终生效阶段；判定结果输出 `threshold_source_stage` / `threshold_source_label` / `overridden_fields` |

### 2.3 结果中的阶段标注（每个判定都带）

```json
{
  "metric_key": "wall_top_horizontal_displacement",
  "rule_id": "WTHD-L1-PILE",
  "threshold_source_stage": 3,
  "threshold_source_stage_display": "第三阶段 · 项目专项方案阈值",
  "threshold_source_label": "【示例】某某项目基坑监测专项方案（经审批）",
  "threshold_source_id": "EXAMPLE-PRJ-PLAN-001",
  "overridden_fields": ["cumulative_mm", "rate_mm_per_day"],
  "selection_used": "conservative"
}
```

## 三、阶段1：通用默认阈值（内置）

**文件**：`thresholds/config/thresholds.generic_default.json`
**来源**：GB 50497-2019《建筑基坑工程监测技术标准》表 8.0.4 / 表 8.0.5

### 3.1 覆盖的监测项（19 项）

| metric_key | 监测项 | 单位 | 限值模式 |
|---|---|---|---|
| `wall_top_horizontal_displacement` | 围护墙顶水平位移 | mm | 位移 |
| `wall_top_vertical_displacement` | 围护墙顶竖向位移 | mm | 位移 |
| `deep_horizontal_displacement` | 深层水平位移 | mm | 位移 |
| `column_vertical_displacement` | 立柱竖向位移 | mm | 位移 |
| `support_axial_force` | 支撑轴力 | 设计值比值 | 上限比 |
| `anchor_axial_force` | 锚杆轴力 | 预应力比值 | 下限比 |
| `groundwater_level` | 地下水位 | mm | 位移 |
| `surface_settlement` | 周边地表竖向位移 | mm | 位移 |
| `building_settlement` | 周边建筑竖向位移 | mm | 位移 |
| `building_inclination` | 周边建筑倾斜 | 比值 | 倾斜 |
| `pipeline_settlement` | 周边管线位移 | mm | 位移 |
| `road_settlement` | 周边道路竖向位移 | mm | 位移 |
| `crack_width_building` | 周边建筑裂缝 | mm | 裂缝 |
| `crack_width_surface` | 地表裂缝 | mm | 裂缝 |
| `basal_heave` | 坑底隆起 | mm | 位移 |
| `wall_internal_force` | 围护墙内力 | 设计值比值 | 上限比 |
| `earth_pressure` | 侧向土压力 | 设计值比值 | 上限比 |
| `pore_pressure` | 孔隙水压力 | 设计值比值 | 上限比 |
| `column_internal_force` | 立柱内力 | — | **无（待补充）** |

### 3.2 三条内置判定策略

| 策略 | 规则 | 规范依据 |
|---|---|---|
| **累计值取小** | `限值 = min(绝对量限值, %H 限值)`；H 未知时退化为绝对量并标记 `PCT_H_NOT_EVALUATED` | GB 50497-2019 表 8.0.4 注 |
| **速率预警** | 达到规定值，**或连续 3 次超过该值的 70%** | GB 50497-2019 第 8.0.3 条 |
| **底板后折减** | 底板浇筑后速率限值 × 0.7 | GB 50497-2019 表 8.0.4 注 |

### 3.3 区间取值策略（规范给区间，系统必须取定值）

GB 50497-2019 表 8.0.4 给的多是区间（如 20~30 mm）。确定性系统必须取确定值：

| 策略 | 含义 | 默认 |
|---|---|:--:|
| `conservative` | 取区间**下限**（偏安全） | ✅ |
| `lenient` | 取区间**上限**（偏宽松） | |
| `midpoint` | 取中值 | |

可在导入文件 `selection_policy.range_resolution` 中覆盖。

### 3.4 危险报警条件（定性，需巡视记录触发）

- **GB 50497-2019 第 8.0.9 条（强制性条文）** 7 条 —— 内置
- **JGJ 120-2012 第 8.2.23 条** 7 条 —— 补充内置
- 阶段2/3 可通过 `danger_alarm_conditions` 追加，同 `code` 覆盖

```

│       └── stage3_专项方案阈值.example.json     ← 示例
└── src/
    ├── threshold_loader.py                    ← 加载 / 合并 / 解析 / 校验
    └── deterministic_calc.py                  ← 四项核心计算 + 判定
```

### 4.2 使用方式

1. 复制示例文件，重命名为 `*.json`（去掉 `.example`）
2. 填写 `stage`（2 或 3）、`source_id`、`source_label`、`source_type`
3. 只写需要覆盖的字段
4. 重启加载即生效

### 4.3 导入前校验

```python
from threshold_loader import ThresholdConfig
cfg = ThresholdConfig()
problems = cfg.validate_import(payload)   # 空列表 = 通过
```

校验项：`stage` 合法、`source_id/source_label/metrics` 必填、每条规则有 `rule_id`/`safety_level`、
`safety_level` 只能是 一/二/三级、数值字段格式正确、`evidence.standard` 必填。

## 五、确定性计算（第二阶段核心功能）

**文件**：`thresholds/src/deterministic_calc.py`

### 5.1 四项核心功能

| # | 功能 | 公式 | 弃权条件 |
|:--:|---|---|---|
| 1 | 累计值 | `cumulative = current − baseline` | 缺 baseline → `MISSING_BASELINE` |
| 2 | 本次变化量 | `single_change = current − previous` | 缺 previous → `MISSING_PREVIOUS` |
| 3 | 变化速率 | `rate = \|single_change\| / interval_days` | 间隔 ≤ 0 → `INVALID_INTERVAL` |
| 4 | 阈值校核 | `utilization = \|value\| / limit`，逐级判定 | 无阈值 → `NO_THRESHOLD` / `NO_APPLICABLE_RULE` |

补充：`expected_interval_days` 的 3 倍以外间隔 → 标记 `IRREGULAR_INTERVAL`，速率结果降为"待复核"。

### 5.2 风险分级

| 等级 | 判定 |
|---|---|
| 正常 | 利用率 < 50% |
| 关注 | 50% ~ 70% |
| 预警 | 70% ~ 100%，或连续 3 次 > 70% |
| 报警 | ≥ 100% |
| **危险报警** | 命中 GB 50497-2019 §8.0.9 / JGJ 120-2012 §8.2.23 定性条件（独立接口，不由数值自动触发） |

## 六、真实数据验证结果

**脚本**：`tools/run_real_data_demo.py`（只读原始文件）
**数据**：隧道 `daily_aligned.csv`（真实观测 2,912 条，已剔除 `filled=1` 填充值）+ `label_thresholds.csv`

| 项 | 结果 |
|---|---|
| 通道数 | 44 |
| 有效观测 | 2,912 |
| 完成判定 | 2,868 |
| **生效阈值阶段** | **全部为阶段2**（导入阈值，100%） |
| 风险分布 | 正常 346 / 关注 130 / 预警 212 / 报警 2,180 |
| 弃权 | 0 |

> **诚实说明一处发现**：报警占比 76%，是因为 `label_thresholds.csv` 的
> `delta_abs_q95 / slope_abs_q95` 是**窗口级（window）统计分位阈值**，
> 直接套用到**逐日（daily step）**观测会显著过度触发。
> 这恰好验证了阈值粒度必须与被判对象一致 —— 后续接入阶段3 专项方案阈值时，
> 必须明确阈值对应的**统计窗口长度**，否则会产生大量误报。
> 此项已作为约束写入导入 schema 的 `evidence.note` 要求。
