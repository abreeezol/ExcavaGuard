# 04 · 日报模块接口契约

> 本文只描述**确定性计算层向日报生成模块的交接契约**。
> 日报生成由后续独立 Agent 实现，**本层不生成任何日报文件**。

---

## 一、边界声明

| 项目 | 归属 |
|---|---|
| 三阶段流水线（数据准备 → 确定性计算 → 规范比对） | **本层已实现** |
| 日报生成（正文、版式、章节组织、建议措施措辞） | **后续独立 Agent 实现** |
| 本层职责 | 把判定结果整理成**结构化、可校验、可追溯**的中间载荷 |
| 本层明确不提供 | 日报正文、日报版式文件、结论性建议措辞、规范原文全文 |

载荷中 `contract.excludes` 字段会在运行期重复声明这一边界，消费方可直接读取，无需依赖本文。

---

## 二、接入方式

### 生产方

```python
from orchestrator import run_pipeline, build_daily_report_input

result  = run_pipeline(records, ctx, registry=registry)   # 三阶段
payload = build_daily_report_input(
    result,
    project={                      # 可选：工程概况，缺省为 null
        "name": "××基坑工程",
        "monitoring_unit": "××监测中心",
        "excavation_stage": "第二道支撑施工完成，开挖至 -12.0m",
        "excavation_depth_m": 12.0,
        "safety_level": "一级",
        "support_type": "地下连续墙",
    },
    points_meta={                  # 可选：测点台账，缺省为 null
        "WTHD-01": {"point_name": "墙顶水平位移监测点 1", "point_type": "墙顶位移"},
    },
    report_date="2026-08-07",      # 可选：报告日期
)
```

三个参数**全部可选**，不传也能产出符合契约的载荷（相关字段为 `null`）。
`project` 中未提供的键会补 `null`，不会被臆造。

### 消费方（日报 Agent）

1. 校验：`python tools/validate_daily_report_input.py <载荷.json>`，退出码 0 表示通过。
2. 读取 `schema` 字段判断契约版本，据此选择解析逻辑。
3. 按需取用：`items`（逐测点成果表）、`alerts`（报警清单）、`review_queue`（待复核）、`summary`（结论概述）、`data_quality`（数据质量说明）。

## 三、载荷结构

顶层 13 个键，全部必填：

| 键 | 用途 |
|---|---|
| `schema` | 契约版本，固定 `excavaguard.daily_report_input/v1` |
| `contract` | 契约自述：生产方、消费方、稳定性规则、不提供内容清单 |
| `generated_from` | 阶段链路，供日报标注口径 |
| `project` | 工程概况（名称、监测单位、报告日期、施工工况、开挖深度、安全等级、支护类型） |
| `context` | 统计口径与**生效阈值来源与阶段** |
| `standards_sources` | 本次实际加载的规范来源清单 |
| `data_quality` | 阶段一质量扫描：问题计数、按码分布、被阻塞期次数 |
| `summary` | 整体汇总：总数、按等级/问题类别/数据来源分布、弃权统计、整体等级 |
| `alerts` | **报警及以上**条目，供「报警清单」「建议措施」直接引用 |
| `review_queue` | **需人工复核**条目（弃权），供「待复核事项」 |
| `items` | 逐条判定明细，供逐测点成果表 |
| `disclaimer` | 免责与使用边界声明 |
| `note` | 说明文字 |

### 明细条目（`items[]`）字段分组

| 分组 | 字段 | 来源 |
|---|---|---|
| 标识 | `point_id` `point_name` `point_type` `metric_key` `metric_name` `timestamp` `data_origin` | 阶段一 + 调用方台账 + 规范库 |
| 本期成果 | `baseline` `previous` `current` `interval_days` `cumulative` `single_change` `rate` `slope` | **阶段二** |
| 判定结论 | `problem_category` `risk_level` `utilization` `checks` `effective_standard` `rule_id` `evidence` | **阶段三** |
| 追溯线索 | `abstain` `abstain_reasons` `flags` `needs_review` | 阶段二/三 |

`metric_name` 取规范库 `display_name`（如 `围护墙（边坡）顶部水平位移`），日报表格可直接用，无需自建映射。

## 四、字段语义要点（消费方必须遵守）

### 1. 风险等级是六值枚举

`正常` / `关注` / `预警` / `报警` / `危险报警` / `未知`

**`未知` 表示弃权，不是"安全"。** 日报中必须归入待复核，不得渲染为正常项。

### 2. 弃权与复核

`abstain` 非空即 `needs_review = true`。典型弃权码：

- 阶段二：`MISSING_CURRENT` `MISSING_BASELINE` `MISSING_PREVIOUS` `INVALID_INTERVAL` `NON_NUMERIC` `NO_DATA`
- 阶段三：`UNKNOWN_METRIC` `NO_APPLICABLE_RULE` `NO_LIMIT` `MISSING_DESIGN_VALUE` `MISSING_H` `DATA_QUALITY_BLOCKED`

`DATA_QUALITY_BLOCKED` 表示该期存在高严重度质量问题（孤立尖峰、非数值、时间戳不可解析、单位不支持、长期平值），**已主动排除在判定之外**，日报中应明确说明该期未参与判定。

### 3. 判据必须带条文依据

每条明细的 `evidence` 含 `standard` / `clause` / `note`；`effective_standard` 含 `origin`（`default_library` 或 `user_uploaded`）、`source_label`、`rule_id`、`overridden_fields`。

日报引用判据时**必须保留规范号与条文号**，并标注实际生效来源。阈值最终须经设计方确认（GB 50497-2019 §8.0.1）。

### 4. 真实数据与模拟数据严格分列

`data_origin` 只有 `real` 与 `simulated` 两值。`context` 中两者分别计数，`summary.by_data_origin` 亦然。

**模拟数据仅用于验证流程对噪音与缺失的鲁棒性，不替代真实数据。** 日报中出现 `simulated` 条目时必须显著标注为模拟数据。

### 5. 限值取小值与降速规则已内嵌

`checks[]` 中每项含 `value` / `limit` / `limit_basis` / `utilization` / `verdict`，已体现：

- 累计值限值取 `min(绝对量, 百分比×H)`
- 变化速率连续 3 次超 70% 升为预警
- 底板浇筑后速率限值 ×0.7（`flags` 含 `POST_SLAB_RATE_REDUCED`）
- 位移不收敛（当前速率 > 序列平均速率 ×1.2）至少预警（`flags` 含 `NON_CONVERGENT`）
- GB 50497-2019 §8.0.9 强制性危险报警条件

消费方**不应重算**这些规则，直接引用 `checks` 即可。

---

## 五、稳定性约定

- **字段只增不改**：新增字段向后兼容，消费方应容忍未知字段。
- **破坏性变更**须升级 `schema` 版本号（`/v2`），消费方按版本分支处理。
- 契约文件：`contracts/daily_report_input.schema.json`（JSON Schema 2020-12）。
- 校验脚本：`tools/validate_daily_report_input.py`。
