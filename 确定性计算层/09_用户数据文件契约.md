# 09 · 用户监测数据文件契约

> 版本：v1（2026-10-10）
> 机器可读版本：`确定性计算层/contracts/monitoring_input.contract.json`（由 `tools/export_input_contract.py` 从代码导出）
> 实现：`pipeline/stage1_data_preparation/file_reader.py` + `ingest.py`

---

## 一、一句话契约

> **用户只需提供「测点编号 / 观测时间 / 监测项目 / 本次观测值 / 单位」五列。**
> 累计值、本次变化量、变化速率所需的初始值、上次值、观测间隔由系统按测点时序**确定性派生**。

---

## 二、为什么这样定

### 2.1 修复的问题（P0-1）

修改前，`parse-monitoring-data` / `normalize-monitoring-data` 两个 Skill 契约把
`baseline_value`、`previous_value`、`interval_hours` 列为**必填**，引擎也直接取这三个字段。

实测后果（2026-10-10 复现）：

```python
# 用户最可能上传的形态
raw = [{'point_id':'WTHD-01','timestamp':'2026-08-01','metric':'wall_top_horizontal_displacement',
        'value':0,'unit':'mm'}, ...]        # 7 期，累计 60mm（远超限值 20mm）
run_pipeline(raw, ctx)
# 修改前 → 弃权 7/7，MISSING_BASELINE + MISSING_PREVIOUS，风险 {'未知': 7}   ← 零输出
# 修改后 → 弃权 1/7，风险 {'未知': 1, '危险报警': 6}                        ← 正确识别
```

**根因**：这三个量是**从时序算出来的**，不是用户应该预先算好的输入。

### 2.2 设计原则

| 原则 | 体现 |
|---|---|
| **不猜、不插补** | 派生规则是确定性的（首期有效观测 = 初始值），不是推断 |
| **显式优先** | 用户已提供的值一律保留，派生不覆盖 |
| **留痕** | 派生字段打 `BASELINE_DERIVED` / `PREVIOUS_DERIVED` / `INTERVAL_DERIVED` 标记，一路透传到判定结果与日报 |
| **只映射不计算** | 读取器只做列名映射与编码识别，数值原样保留，合法性交质量扫描判定 |
| **缺必填即拒收** | 明确列出缺了哪几列，不猜列、不补列 |

## 三、文件要求

| 项 | 要求 |
|---|---|
| 格式 | CSV / TSV / TXT / XLSX（`.xlsx` 需 `openpyxl`；未安装时提示另存为 CSV） |
| 编码 | 按序自动尝试：`utf-8-sig` → `utf-8` → `gb18030` → `gbk` → `big5` → `latin-1` |
| 分隔符 | 自动识别 `,` `;` `\t` `|`（取表头行出现最多者，默认逗号） |
| 表头 | 必须有表头行；列顺序任意；列名可用中英文常见写法 |
| 空行 | 全空行自动跳过 |

---

## 四、列契约

### 4.1 必填列（5 个）

| 规范字段 | 中文含义 | 常见别名（部分） |
|---|---|---|
| `point_id` | 测点编号 | 测点、测点编号、测点号、点号、编号、point、sensor_id |
| `timestamp` | 观测时间 | 观测时间、日期、时间、监测日期、date、datetime |
| `metric` | 监测项目 | 监测项目、监测项、项目、参数、metric_key、item |
| `value` | 本次观测值 | 观测值、本次观测值、实测值、数值、读数、value、reading |
| `unit` | 单位 | 单位、计量单位、unit |

**缺任一列 → 拒收**，返回 `missing_required` 清单与提示文案。

### 4.2 可派生列（缺失时系统派生）

| 规范字段 | 派生规则 |
|---|---|
| `baseline_value` | 该测点**首个有效观测**值 |
| `previous_value` | 该测点**前一个有效观测**值；首期为 `null` |
| `interval_days` | 本期与前一有效观测的**时间差（天）**；首期为 `null` |
| `interval_hours` | 同上，读取时 ÷24 转为天 |

- 「有效观测」= 数值可解析的记录；**空值与非数值不参与派生**；
- 跨缺测期时，间隔按**真实天数**计算（不按 1 天）；
- **显式提供的值优先**，派生不覆盖。

### 4.3 可选列

| 规范字段 | 说明 |
|---|---|
| `direction` | 方向。支持 `positive/negative`、`正/负`、`+/-`、`上升/下降`、`隆起/沉降` 等 25 种写法；无法识别记 `UNKNOWN_DIRECTION` 并默认 `positive` |
| `data_origin` | `real` / `simulated`；缺省 `real`；非法值记 `UNKNOWN_DATA_ORIGIN` |
| `note` | 备注，原样保留 |

> **`direction` 不参与数值计算**，仅作元数据与展示；数值的正负由 `value` 本身携带。

## 五、单位与量纲

| 量纲 | 支持单位 | 换算为 |
|---|---|---|
| 长度 | `mm` `cm` `dm` `m` `km` | **mm** |
| 压强 | `pa` `kpa` `mpa` | **kPa** |
| 力 | `n` `kn` `mn` | **kN** |
| 无量纲 | `1` `ratio` `%` `度` `°` 等 | 原样保留 |
| 温度 | `℃` `°C` `c` `celsius` `摄氏度` | 原样保留（不做温标换算） |

**无法识别的单位** → 原样保留并标记 `UNSUPPORTED_UNIT`（高严重度 → 阻塞该期判定并转人工复核）。
**不猜单位、不静默换算**。

## 六、监测项名称映射

用户可用三种写法，系统统一映射到规范库的 `metric_key`：

| 写法 | 示例 | 映射结果 |
|---|---|---|
| metric_key | `wall_top_horizontal_displacement` | 自身 |
| 规范库标准名 | `围护墙（边坡）顶部水平位移` | `wall_top_horizontal_displacement` |
| 去括号简称 | `围护墙顶部水平位移` | 同上 |
| 常见俗称 | `测斜` / `墙顶水平位移` / `地表沉降` / `孔压` | 对应 metric_key |

共 **88 条别名**（含 22 个监测项的标准名、去括号名与俗称）。
归一化后若出现歧义（多个监测项归一为同一名称），**该名称不收录**，避免映射错误。

## 七、最小示例

```csv
point_id,timestamp,metric,value,unit,direction
WTHD-01,2026-08-01,wall_top_horizontal_displacement,0.0,mm,positive
WTHD-01,2026-08-02,wall_top_horizontal_displacement,2.1,mm,positive
WTHD-01,2026-08-03,wall_top_horizontal_displacement,4.6,mm,positive
```

等价的中文 GBK 版本同样可用：

```csv
测点编号,观测日期,监测项目,本次观测值,单位,方向
WTHD-01,2026-08-01,围护墙顶部水平位移,0.0,mm,正
WTHD-01,2026-08-02,围护墙顶部水平位移,2.1,mm,正
WTHD-01,2026-08-03,围护墙顶部水平位移,4.6,mm,正
```

**端到端实测**（中文 GBK 表 → 三阶段）：

```
读取: 编码=gb18030  行数=7  映射=6 列
metric 映射结果 : wall_top_horizontal_displacement
阶段二弃权      : 1 / 7          （仅首期因无上次值弃权）
风险分布        : {'未知': 1, '危险报警': 6}
末条等级        : 危险报警   利用率 4.0
规范依据        : GB 50497-2019 表8.0.4
限值依据        : min(绝对量 20 mm, 0.2%×H=40 mm) = 20 mm
```

## 八、工程条件（不由文件提供）

以下工程条件**必须由调用方单独提供**，文件里没有：

| 条件 | 用途 | 缺失后果 |
|---|---|---|
| `safety_level` | 选择阈值档位（一/二/三级） | 匹配不到规则 → `NO_APPLICABLE_RULE` 弃权 |
| `support_type` | 选择阈值档位（地连墙/灌注桩/土钉墙…） | 同上 |
| `excavation_depth_m` | `%H` 类限值换算 | 见 `06_..._目标实现度评估.md` **P1-2**：目前退化为只用绝对量限值，**可能偏松** |
| `design_values` | 内力/轴力类设计值校核 | `MISSING_DESIGN_VALUE` 弃权 |
| `post_slab_from` | 底板浇筑后速率 ×0.7 | 不折减（偏松） |

> **P1-2 尚未修复**：缺 H 时应用弃权（`MISSING_H`）而非用绝对量限值替代。
> 这是文件契约之外的**下一项待办**。
