# 基坑智守 · 三阶段流程与规范比对说明

> 本文说明确定性计算层的流程语义、规范来源与扩展接口。
>
> **阶段含义（唯一口径）**
>
> | 阶段 | 含义 |
> |---|---|
> | 阶段一 | **数据准备** —— 用户上传的现有数据 与 模拟数据，统一作为风险识别参数的输入依据 |
> | 阶段二 | **确定性计算** —— 累计值、本次变化量、变化速率、趋势斜率 |
> | 阶段三 | **规范比对** —— 把计算结果与规范判据比对，识别风险并分级 |
>
> 三个阶段是**流程上的先后关系**，不是方案的递进关系。

---

## 一、流程总览

```
                        ┌──────────────────────────────────────┐
                        │  阶段一 · 数据准备                    │
                        │                                      │
   用户上传的现有数据 ──►│  接入 → 归一化 → 噪音与缺失识别       │
                        │  （保留 data_origin 标识，不修改原值） │
   模拟数据 ───────────►│                                      │
   （仅用于健壮性验证）  └───────────────┬──────────────────────┘
                                        │ 风险识别参数
                                        ▼
                        ┌──────────────────────────────────────┐
                        │  阶段二 · 确定性计算                  │
                        │  累计值 / 本次变化量 / 变化速率 / 斜率 │
                        │  输入不足 → 弃权，不插补、不猜测       │
                        └───────────────┬──────────────────────┘
                                        │ 确定性结果 + 公式 + 输入值
                                        ▼
                        ┌──────────────────────────────────────┐
                        │  阶段三 · 规范比对                    │
                        │  默认规范库（基坑智守项目相关规范）     │
                        │  + 用户上传规范（可选，字段级覆盖）      │
                        │  → 风险识别与分级                     │
                        └───────────────┬──────────────────────┘
                                        │ 结构化中间结果
                                        ▼
                              日报生成模块（后续接入）
```

**关键约束**

- 阶段一只做归一化与**识别**，不修改原值、不插补、不静默丢弃；
- 阶段二相同输入必得相同输出，绝不引入模型推断；
- 阶段三每一次判定都写明**本次实际生效的规范来源**。

## 二、阶段一 · 数据准备

### 2.1 两类输入的地位

| 输入 | 标识 | 地位 |
|---|---|---|
| 用户上传的现有数据 | `data_origin = "real"` | 真实来源，是判定的主依据 |
| 模拟数据 | `data_origin = "simulated"` | **仅用于验证流程健壮性，不替代真实数据** |

两者在阶段一统一接入、归一化，产出同一套「风险识别参数」结构，再一起进入阶段二。
统计时始终**分开计数**（`by_data_origin`）。

### 2.2 模拟数据的用途边界

模拟数据是向**真实数据副本**注入受控噪声后得到的"带病"数据集，用途只有一个：
**验证 Agent 是否具备处理用户上传数据中噪音与缺失的能力**。

| 用途 | 说明 |
|---|---|
| ✅ 验证健壮性 | 异常值、空值、格式不一致能否被识别而不是崩溃或静默出错 |
| ❌ 替代真实数据 | 禁止。不用于对外输出工程结论 |
| ❌ 与真实数据合并统计 | 禁止。全程带 `simulated` 标识单独计数 |

噪声预设：`clean / light / medium / heavy / missing_only / outlier_only / format_only`。

**强制标识规则**

1. 输出文件名必须含 `SIMULATED`；
2. 每条记录强制携带 `data_origin = "simulated"`；
3. 保留 `source_dataset` 字段，标明由哪份真实数据派生；
4. 汇总中 `simulated_records` 与 `real_records` 分列。

### 2.3 噪音与缺失识别清单（识别，不修改）

| 问题码 | 含义 | 严重度 |
|---|---|---|
| `MISSING_VALUE` | 空值 / 缺测 | 中 |
| `MISSING_BASELINE` | 缺初始值，累计值不可算 | 中 |
| `MISSING_PREVIOUS` | 缺上次值，本次变化量不可算 | 中 |
| `OUTLIER` | **孤立尖峰（粗差）** 或超出物理量程 | 高 |
| `NON_NUMERIC_VALUE` | 数值字段非数值（格式不一致） | 高 |
| `UNPARSED_TIMESTAMP` | 日期格式无法解析 | 高 |
| `UNSUPPORTED_UNIT` | 单位无法识别（格式不一致） | 高 |
| `UNIT_INCONSISTENT` | 同测点单位前后不一致 | 中 |
| `FORMAT_INCONSISTENT` | 点号/日期/单位格式不统一 | 低 |
| `DUPLICATE_RECORD` | 同测点同时间重复记录 | 中 |
| `TIMESTAMP_OUT_OF_ORDER` | 时间倒流 | 中 |
| `IRREGULAR_INTERVAL` | 观测间隔显著异常 | 低 |
| `FLATLINE` | 连续多期数值不变，疑似传感器漂移 | **高** |
| `TIME_SERIES_TOO_SHORT` | 有效观测不足，无法计算速率 | 低 |

### 2.4 粗差为什么不用「原始值 ±kσ」

监测序列本身带有趋势（开挖引起的持续变形），趋势尾部天然偏离均值。
对原始值做统计离群会把**真实突变**和**趋势尾部**误判为粗差，进而把真实险情当成数据错误屏蔽掉——属危险的漏判。

因此粗差只识别**孤立尖峰**：相邻两步大小相当（较小者 ≥ 较大者 × 0.5）、方向相反、总摆幅 ≥ 5。

| 形态 | 判据 | 处置 |
|---|---|---|
| 孤立尖峰 | 跳变后**立即跳回** | 判为粗差 → 该期及相邻期弃权转人工复核 |
| 台阶跳变 | 跳变后**维持在新水平** | 判为**真实变形** → 正常进入判定，不得屏蔽 |

### 2.5 高严重度质量问题的阻塞规则

上表中标记为**高**的问题码，其所在期次**不得参与风险判定**，一律弃权并转人工复核
（弃权码 `DATA_QUALITY_BLOCKED`，问题类别归入「数据质量异常」）。

理由：粗差会把「正常」误判为「报警」，传感器漂移会把「报警」误判为「正常」，
两个方向的漏判都会危及安全，因此一律阻塞而不是"带病判定"。

> 空值与非数值必须区分：空值 → `MISSING_VALUE`（中，属缺测）；
> 非空但转不成数字 → `NON_NUMERIC_VALUE`（高，属格式错误，需阻塞）。

## 三、阶段二 · 确定性计算

### 3.1 四项核心计算

| 计算项 | 公式 | 单位 |
|---|---|---|
| 累计值 | `cumulative = current − baseline` | mm / kN / kPa |
| 本次变化量 | `single_change = current − previous` | mm / kN / kPa |
| 变化速率 | `rate = \|single_change\| / interval_days` | mm/d |
| 趋势斜率 | `slope = Σ((x−x̄)(y−ȳ)) / Σ((x−x̄)²)`（最小二乘） | mm/d |

### 3.2 弃权规则

输入不足时**弃权**并给出明确弃权码，绝不猜测、绝不插补、绝不静默跳过。

| 弃权码 | 含义 |
|---|---|
| `MISSING_CURRENT` | 缺少本次观测值 |
| `MISSING_BASELINE` | 缺少初始值，累计值不可计算 |
| `MISSING_PREVIOUS` | 缺少上次观测值，变化量/速率不可计算 |
| `INVALID_INTERVAL` | 间隔 ≤ 0，速率不可计算 |
| `NON_NUMERIC` | 观测值非数值 |
| `NO_DATA` | 无可用记录 |

## 四、阶段三 · 规范比对

### 4.1 规范来源

#### （1）默认规范库 —— 始终生效

- **目录**：`C:\Study\bisai\Hai AI Agent\基坑智守项目相关规范`
- **定位**：该目录内的规范被视为**覆盖大多数情况的通用规范**，是阶段三的默认判据来源
- **规范库索引**：`standards/default/规范库索引.json`（由 `tools/build_standards_index.py` 自动生成）
- **条文级阈值**：`standards/default/thresholds_gb50497_2019.json`

索引统计（30 本，按相关性分档）：

| 相关性 | 数量 | 代表规范 |
|---|---|---|
| primary（直接判据） | 4 | GB 50497-2019、GB 55003-2021、JGJ 120-2012 |
| secondary（配套判据） | 7 | GB 50007-2011、JGJ 311-2013、GB 51004-2015、GB 50202-2018 等 |
| conditional（条件适用） | 4 | JGJ 111-2016、GB 55030-2022 等 |
| reference（背景参考） | 15 | 其余 |

其中 18 本可提取文本，供条文级溯源。

#### （2）用户上传规范 —— 可选

- **目录**：`standards/user_uploaded/`
- 用户可自行放入地方规程或项目专项方案的阈值 JSON
- **用户未上传时不作任何特殊处理**：不报错、不告警、不输出缺失提示，直接使用默认规范库

#### （3）生效规则

- 同一监测项同一规则下，**用户上传规范的字段覆盖默认规范库**；
- 未显式给出的字段**继承**默认规范库，不会出现"覆盖即清空"；
- 每次判定都输出实际生效来源：

```json
"effective_source": {
  "origin": "default_library",
  "origin_display": "默认规范库（基坑智守项目相关规范）",
  "source_id": "GB50497-2019",
  "source_label": "GB 50497-2019《建筑基坑工程监测技术标准》",
  "rule_id": "WTHD-L1-PILE",
  "overridden_fields": []
}
```

`origin` 取值：`default_library`（默认规范库）/ `user_uploaded`（用户上传规范）。

### 4.2 上传接口

```python
from standards_registry import upload_standard, write_upload_template, clear_user_standards

# 1) 导出模板给用户填写
write_upload_template("standards/user_uploaded/user_standard_template.json")

# 2) 校验并写入（只写 user_uploaded，绝不触碰默认规范库与原始数据）
res = upload_standard(payload)      # {"ok": True, "path": ...} 或 {"ok": False, "problems": [...]}

# 3) 移除
clear_user_standards()
```

上传前强制校验项（不通过则拒绝写入）：

- 必须提供 `source_id`、`source_label`、`metrics`；
- 每条规则必须有 `rule_id`；
- `safety_level` 只允许 `一级 / 二级 / 三级`；
- 限值字段必须是数值或 `{min, max}`；
- `evidence` 必须给出 `standard`（条文出处），否则结果无法溯源。

### 4.3 三条内置比对策略

| 策略 | 规则 | 依据 |
|---|---|---|
| 区间取值 | 规范给区间时**取下限**（偏安全），可选 `conservative / lenient / midpoint` | 确定性系统必须取确定值 |
| 累计值取严 | `min(绝对量限值, 相对 H 的限值)`；H 未知时退化为绝对量并标记 `PCT_H_NOT_EVALUATED` | GB 50497-2019 表 8.0.4 注 |
| 速率判定 | 达到规定值 **或** 连续 3 次超过该值的 70% | GB 50497-2019 第 8.0.3 条 / 表 8.0.4 注 |
| 底板浇筑后 | 位移速率限值 × 0.7 | GB 50497-2019 表 8.0.4 注 |

> 相对 H 的限值换算：`limit_mm = pct[%] × H[m] × 10`

### 4.4 风险分级

设利用率 `u = 实测值 / 限值`：

| 等级 | 触发条件 | 依据 |
|---|---|---|
| 正常 | `u < 0.50` | 限值充裕 |
| 关注 | `0.50 ≤ u < 0.70` | 接近管控区间 |
| 预警 | `0.70 ≤ u < 1.00`，或连续 3 次速率 > 70% 速率限值 | GB 50497-2019 第 8.0.3 条 / 表 8.0.4 注 |
| 报警 | `u ≥ 1.00` | GB 50497-2019 第 8.0.7 条 |
| 危险报警 | 触发 GB 50497-2019 第 8.0.9 条任一条件，或 `u ≥ 1.20` | GB 50497-2019 第 8.0.9 条（强制性条文） |
| 未知 | 输入不足、无适用判据 | 弃权，不做推断 |

多项校核（累计值 / 速率 / 设计值比例 / 倾斜）同时存在时，**取其中的最高等级**。

**不收敛判据（JGJ 120-2012 §8.2.23-2）**

当 `|当前速率| > |序列最小二乘平均速率| × 1.2` 且速率 ≥ 0.05 时，判定为「位移速率增长且不收敛」，
标记 `NON_CONVERGENT`，等级**至少升级为预警**。

原理：加速序列的瞬时速率高于平均速率，收敛序列则相反。该判据用于捕捉
「累计值尚不高但变形在加速」的情形 —— 这类情况单看累计值会被漏判。

### 4.5 问题类别

判定结果按监测项归入问题类别，供日报与统计使用：

| 问题类别 | 覆盖监测项 |
|---|---|
| 变形过大 | 墙顶水平/竖向位移、深层水平位移、立柱竖向位移、地表/建筑/管线/道路沉降、建筑倾斜、坑底隆起 |
| 渗漏水与地下水异常 | 地下水位、孔隙水压力、渗漏水量（**待补充**） |
| 支护受力异常 | 支撑轴力、锚杆轴力、围护墙内力、立柱内力、土压力 |
| 裂缝发展 | 建筑裂缝宽度、地表裂缝宽度 |
| 数据质量异常 | 由阶段一的质量问题码驱动，不属于任何监测项 |

### 4.6 弃权码

| 弃权码 | 含义 |
|---|---|
| `ABSTAIN_FROM_STAGE2` | 阶段二已弃权，无可比对结果 |
| `UNKNOWN_METRIC` | 规范库中不存在该监测项的判据 |
| `NO_APPLICABLE_RULE` | 当前安全等级/支护形式组合下无适用判据 |
| `NO_LIMIT` | 当前条件下未给出可比对的限值 |
| `MISSING_DESIGN_VALUE` | 需按设计值校核但未提供 |
| `MISSING_H` | 需按 H 校核但未提供 |
| `DATA_QUALITY_BLOCKED` | 该期存在高严重度数据质量问题，按安全原则不参与判定，转人工复核 |

## 六、真实数据验证（真实数据优先）

`tools/run_real_data_demo.py` 用目录内**真实存在**的隧道多传感器数据集
（Zenodo 10.5281/zenodo.20768869）跑通三阶段流程，2,868 条有效观测（已剔除填充值）：

| 组别 | 规范来源 | 结果 |
|---|---|---|
| **A｜未上传用户规范** | 仅默认规范库 | 生效来源 `default_library`；2,868 条全部弃权（`UNKNOWN_METRIC`），**未产生任何缺失告警** |
| **B｜上传真实数据派生的规范** | 默认规范库 + 用户上传 | 生效来源 `user_uploaded`；2,868 条全部有判据：正常 315 / 关注 112 / 预警 258 / 报警 163 / 危险报警 2007 / 未知 13 |

验证到的两点：

1. **用户未上传规范时不作特殊处理**——A 组静默使用默认规范库，不报错不告警；
2. **用户上传接口可用**——B 组按真实数据派生的阈值完成比对，逐条生效来源均为 `user_uploaded`。

> ⚠️ B 组「危险报警」占比偏高，是因为 `label_thresholds.csv` 的阈值是**窗口级 95 分位**统计量，
> 而本脚本按**逐日步长**判定，二者粒度不同。该结论与基坑工程无关，
> 恰好印证了「阈值粒度必须与被判对象一致」这一工程常识。

## 七、模拟数据集（多风险场景覆盖）

### 7.1 隔离措施

模拟数据写入**独立目录** `data_simulated/`，与 `基坑智守项目相关数据/`、`derived/` 完全隔离：

| 措施 | 落地方式 |
|---|---|
| 目录隔离 | `data_simulated/`，不在原始数据目录之下，也不与 `derived/` 混放 |
| 文件名标注 | 文件名统一含 `SIMULATED` |
| 数据内标识 | 每条记录带 `data_origin = "simulated"`、`is_simulated = TRUE` |
| 溯源字段 | 每条记录带 `source_dataset = "SIMULATED-EXCAVAGUARD-V1"` |
| 分开统计 | 汇总中 `real_records` 与 `simulated_records` 分列，绝不合并 |

### 10.1 日报生成

```python
from orchestrator import run_pipeline, build_daily_report_input

result  = run_pipeline(records, ctx, registry=registry)
payload = build_daily_report_input(
    result,
    project={...},        # 可选：工程概况（名称、监测单位、施工工况、开挖深度、安全等级、支护类型）
    points_meta={...},    # 可选：测点台账（测点名称、类型）
    report_date="...",    # 可选：报告日期
)
```

三个参数全部可选，不传也能产出符合契约的载荷（相关字段为 `null`，不会被臆造）。

`build_daily_report_input()` 输出 `excavaguard.daily_report_input/v1` 载荷，顶层 13 个键：

| 键 | 用途 |
|---|---|
| `schema` / `contract` | 版本标识与契约自述（含"不提供日报正文"的边界声明） |
| `generated_from` | 阶段链路，供日报标注口径 |
| `project` | 工程概况 |
| `context` | 统计口径 + **生效阈值来源与阶段** |
| `standards_sources` | 本次实际加载的规范来源清单 |
| `data_quality` | 阶段一质量扫描结果与阻塞期次数 |
| `summary` | 整体汇总（按等级/问题类别/数据来源分布、弃权统计、整体等级） |
| `alerts` | 报警及以上条目，供「报警清单」「建议措施」直接引用 |
| `review_queue` | 需人工复核条目（弃权），供「待复核事项」 |
| `items` | 逐条明细，供逐测点成果表 |
| `disclaimer` / `note` | 免责与说明 |

明细条目分四组字段：**标识**（测点、监测项及其中文名、时间、数据来源）、
**本期成果**（基准值、上次值、本次值、间隔、累计值、本次变化量、速率、斜率）、
**判定结论**（问题类别、风险等级、利用率、逐项校核 `checks`、生效规范、规则号、条文依据）、
**追溯线索**（弃权码及中文说明、过程标记、是否需复核）。

契约与校验：

| 文件 | 作用 |
|---|---|
| `contracts/daily_report_input.schema.json` | 机器可读契约（JSON Schema 2020-12），字段只增不改 |
| `tools/validate_daily_report_input.py` | 契约校验工具，消费方可前置校验 |
| `04_日报模块接口契约.md` | 完整字段语义与消费约定 |

**本层不生成符合日报规范的文件**，仅提供接入点。日报正文、版式、结论与建议措辞
由后续独立 Agent 负责。
