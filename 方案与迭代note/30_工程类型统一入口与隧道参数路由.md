# 工程类型统一入口与隧道参数路由（2026-11-04）

## 用户流程

登录 → 选择获授权工程（新建时只选择基坑工程或隧道工程）→ 确认必要工程条件 → 上传/选择监测数据 → 程序识别测项和时间范围 → 选择日报/周报/月报 → 通用三Agent编报、审查及人工最终确认。

用户不选择适配器、知识库或数据库连接，也不编辑工程配置JSON。隧道只有一个业务入口，盾构、矿山/钻爆、明挖作为必要工程参数；轨道交通、公路、城市道路以及阶段、特殊地质同理。不能从一列沉降数值可靠推断真实工法，因此工程条件由用户首次确认并日常复用，测项和日期由程序读取。

## 后台处理

工程类型固定映射到专业处理入口。隧道共用同一个运行实现与16本独立规范候选库，不为各工法或测项创建新适配器。程序依据已确认条件筛选规范，依据数据测项选择计算和控制值；继续保留Supervisor、报告Agent、审计Agent及通用Skill协同。

前端只返回基坑工程、隧道工程两个业务选项；后台工程绑定和版本留痕仍保留，供追溯与防止运行混用，不作为用户选择项。隧道工程条件区只展示必要分类字段，上传后再按实际测项显示输入含义、控制值依据及限值确认。未提供控制要求的测项列为待核，不能借用其他测项标准。

已有隧道工程在读取时接入同一个处理入口，保存确认后写入统一绑定。原地表/建筑沉降控制要求按原有作用范围分别保留，不推广到拱顶或收敛。缺少的工程系统及地质条件不擅自猜测，需要首次补齐必要工程信息。原始资料、记录人、哈希及历史报告不覆盖；历史资源只用于兼容和复核，不是另一项可选产品。

工程辅助资料兼容既有隧道标签，同时继续严格核对项目ID及原件/内容指纹。改变工法后由程序重新派生案例工法条件，工程师无需重复维护该内部字段。规范检索按当前工程配置执行，项目之间仍隔离。
