# 全规范检索与引用验收

> 本文记录全目录功能首次验收。后续已升级8路滚动并发并修正模型审查职责，当前实现与性能结果以[17号说明](17_检索并发与模型稳定性优化.md)为准。

实现与验收日期：2026-10-27。针对本次本地改动，模板版本为 `deep-pit-monitoring-report/service-v5`，未自动提交或推送。

## 改动与原因

旧普通检索同时在请求与返回候选中锁定GB50497-2019，每主题只保留少量命中。模型即使知道其他规范，也无法拿到对应证据。正文及部分附表还直接展示evidence_ids，读者看到的是切片码。

本次保留三Agent和原Skill，改为程序控制的逐目录规范检索、全部测项跨规范检索，以及原多日预警追加核查。默认目录30份来源按规范编号/优选来源去重为29本，逐本查询最多4条、逐测项最多8条、最多4路并发。模型遗漏的合法测项主题由程序补齐，未知主题仍拒绝。主证据按规范轮转去重最多96条，多日预警补充后最多144条；记录目录、命中/未命中/效力、查询轨迹与预算截断。不能为凑本数强行引用无关内容。

`coverage`与按测项的`comparisons`进入冻结证据快照。规范条件差异交工程师判断，不自动替换数值阈值、修改风险或发布预警。目录状态依赖团队维护，未命中不能证明没有要求，目录覆盖不等于逐字穷举所有条文或实时全网法规更新核验。

## 报告与引用

正文、工况、建议、附表分析及备注、超限表和周期明细显示《规范名称》+编号+条文；源文件定位去掉#chunk片段。机器证据ID、来源原文和哈希保留在内部契约中，不以书名替代唯一主键。

新增“规范证据索引”“规范检索覆盖”“多规范要求对照”三张表，并同步输出到附表Markdown。数值判据名称来自冻结判据与现有规范目录；RAG引用明确为解释候选，不能冒充生效阈值。缺来源或引用不存在的ID拒绝出报，无法识别的判据列为待复核。

独立审计重建全部文件和单元格，名称错配、源元数据被改动或统计格变化均拒绝，刷新文件哈希不能绕过。模型语义审查聚焦已写正文、附表模型分析及其实际引用来源；确定性审计仍读取完整规范表格，避免把全部OCR正文重复发给模型导致上下文膨胀。未成功调用审计模型不能当作真实语义验收通过。

验收还修复了Windows映射盘符下载路径误判：先规范化工作区根，再严格比较其下文件真实路径，正常盘符映射可下载，报告文件符号链接仍拒绝。旧已保存报告不改写，需重新生成才使用v5展示。

## 复现

使用同一操作系统的Node/Python依赖，Node24，Python需openpyxl。在仓库根目录：

```bash
npm run test:standards
npm run test:period
npm test
python -B 确定性计算层/pipeline/tests/test_period_reports.py
```

POSIX符号链接探测在Windows上显式跳过，Windows盘符映射及下载由Vitest纵向测试覆盖。Windows映射路径初始化可能较慢，宽表测试beforeAll预算为45秒；Markdown断言统一换行符，不改变报告内容。

真实Pinecone（Bash示例，须已有配置与可用网络；模型模拟）：

```bash
EXCAVAGUARD_TEST_STANDARD_LIVE=1 EXCAVAGUARD_TEST_STANDARD_MODEL=0 node --env-file=.env.local --import ./tools/test/node-typescript-loader.mjs tests/standard-review.node.test.mjs
```

纯模拟数据真实模型（可能产生正常API用量）：

```bash
EXCAVAGUARD_TEST_SYNTHETIC_MODEL=1 node --env-file=.env.local --import ./tools/test/node-typescript-loader.mjs tests/standard-review-model-live.mjs
```

如需指定解释器，在运行前设置EXCAVAGUARD_PYTHON。本次WSL原生检查使用VS Code内已有Linux Node和现有openpyxl目录，未手动修改node_modules；原Windows依赖的全量Vitest通过临时映射盘符运行，未改系统默认Node/npm。
