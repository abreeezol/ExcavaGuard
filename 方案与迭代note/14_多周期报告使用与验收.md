# 多周期报告使用与验收

实现日期：2026-10-27。范围：现有单操作者、单份上传文件、多周期编报与重复预警规范核查；不改变多用户权限或风险阈值。

## 工作台使用

1. 按原流程上传 CSV/TSV/XLSX，提供设计深度等工程条件。文件应包含区间内记录及可用的此前历史，系统不会从未上传的数据中补历史。
2. 在“报告周期”选择日报、周报、月报或自定义。周报以所选结束日向前取7个自然日；月报选择所属月任一天，覆盖完整自然月；自定义直接填写开始和结束日期。
3. 选择 AI 模式或确定性模板并运行。AI 模式保持原有模型和规范检索；模板模式不调用模型与 RAG。自定义区间含首尾日，最多366天；选定区间完全无记录时拒绝出报。
4. 结果展示覆盖天数、逐日风险变化、重复预警、未知与缺口。报告三件套增加周期统计、每日变化、周期逐日明细；A～F 附表采用各通道最严重的一条原观测并保留日期，不能当作期末值。
5. 审计通过后下载当前草稿，由工程师接受、退回或拒绝。历史可恢复所选周期；改日期后新建运行，不复用旧审计。最多两轮自动修订不变。

现有宽表验收文件 `final_test/监测数据整合_7天_10分钟输入.xlsx` 实际日期为 **2026-10-05～2026-10-11**，选择该周可看到85个通道、595条日末判定。选择自然月时，其他日期如实显示缺测，不会补齐成正常。

## API

沿用 `POST /api/runs`，新增可选字段；不传 `report_period` 即原日报行为：

```json
{
  "project_id": "11111111-1111-4111-8111-111111111111",
  "monitoring_file_id": "替换为实际上传返回的UUID",
  "report_date": "2026-10-11",
  "report_period": {
    "type": "custom",
    "start_date": "2026-10-05",
    "end_date": "2026-10-11"
  },
  "context": {
    "safety_level": "一级",
    "support_type": "地下连续墙",
    "excavation_depth_m": 20
  },
  "options": { "generate_report": true, "report_mode": "ai" }
}
```

`type` 可为 `weekly`、`monthly`、`custom`；周报须7天，月报须完整自然月。周期 `report_date` 必须等于 `end_date`。非法字段/区间返回400；无可用数据由原引擎错误通道返回明确失败，不输出空白正常报告。

日报仍为 `excavaguard.daily_report_input/v1`；周期为独立 `excavaguard.period_report_input/v1`。`period.daily_items` 为全部区间事实，`items` 为每通道最严重原观测，统计及哈希由 Python 生成并复核。最多50000条周期明细，超出须缩短区间或减少通道。

## 规范扩展核查的含义

- 原 GB50497-2019 主题检索不变；同点、同测项至少两个不同日期达到“预警”及以上时追加检索，不要求连续，同一天多条不重复计天。另行统计最长连续预警天数。
- 扩展查询覆盖监测加密、复测、现场复核和异常处置，解除单一版本限制，保留现行状态过滤；最多六组，每组8条。通用基坑监测频率条文也可作为候选。
- `extended_review` 保留查询、命中证据 ID、相对原检索的补充候选及缺口。报告、审计和界面共同可见；服务不可用时停止 AI 报告交付，保留检查点。
- **“补充候选”是本次检索新发现的条文，不等同于新颁布规范。** 只搜索当前配置知识库；未联网核验全网最新版本，元数据中的 `active` 依赖知识库维护。未命中不代表没有额外要求，须工程师继续查证并确认适用性；不自动改变计算阈值或风险级别。

## 事实口径和限制

保留结束日前的历史计算基准、前值与趋势，不以区间开始日重新归零，不使用结束日之后的记录。按 Asia/Shanghai 自然日统计，缺测不插值、未知不算正常。周期首末观测不一定恰在首末日期，通道日期见明细。宽表仍沿用现有每日末值及日内来源统计，日内峰值未经独立风险判定。工程条件和阈值按本次输入统一适用，期间变更须分段重算。没有巡视记录不生成表 G。
