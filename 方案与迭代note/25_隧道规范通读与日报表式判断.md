## 3. 表式判断：不能照搬基坑，规范有专属格式

### 3.1 依据条文

- **GB 50911-2013 第 11.0.5 条**：日报应包含 ①工程施工概况 ②现场巡查信息 ③监测项目日报表
  （仪器型号、监测日期、观测时间、天气、累计变化值、变化速率值、控制值、监测点平面位置图）
  ④数据与巡查分析 ⑤结论与建议；并明确"可采用本规范**附录 D** 的样式"。
- **附录 D 监测日报表**：D.0.1 水平位移、竖向位移；D.0.2 深层水平位移；D.0.3 轴力（拉力）；
  D.0.4 应力、压力。
- **附录 C 现场巡查报表**：C.0.1 明挖法和盖挖法、C.0.2 盾构法、C.0.3 矿山法（按工法分表）。
- **GB/T 51310-2018 13.4.2**：报告分日报/周报/月报/年报，但未另给表式 → 表式仍以附录 D 为准。
- **JTG/T 3660-2020 附录 E/F**：周边位移、拱顶下沉**量测记录表**（现场记录，含第一次/第二次/
  第三次观测值、温度修正），属原始记录，**不是日报表**。

### 3.2 差异对照（为什么不能直接复用）

| 项目 | 基坑（GB 50497 附录 A~G） | 隧道（GB 50911 附录 D） |
|---|---|---|
| 分类数 | 6 类（位移/深层位移/内力/轴力/水位/裂缝） | **4 类** |
| 拱顶沉降、净空收敛 | 无对应表 | **同属 D.0.1**（水平/竖向位移） |
| 控制值 | 无独立列（写入备注） | **独立列**，且分"累计变化值 / 变化速率值"两子列 |
| 初始值 | 表 A 无 | **D.0.1 有** |
| 上次累计变化量 | 无（只有"累计变化"） | **有** |
| 预警等级 | 无独立列 | **独立列** |
| 监测日期 | 每行一列 | 放**表头**，表体不重复 |
| 仪器信息 | 型号/编号/检定日期 | 同左（另含出厂编号） |
| 轴力口径 | 累计变化 | **上次测值 / 本次测值**（绝对读数） |
| 巡查表 | 表 G 一张通用清单 | **C.0.1/C.0.2/C.0.3 按工法三张** |

一句话：把基坑表套到隧道上，会缺"控制值/预警等级/初始值"三列，也多出不该有的"监测日期"列，
等于交了一份看起来完整、实际不合规的日报。

### 3.3 已做的改造

| 改动 | 文件 |
|---|---|
| 新增附录 D 表式注册表（4 张，含两行合并表头、表头字段、签署栏） | `skills/render-daily-report/scripts/tunnel_appendix_forms.py` |
| 渲染器改为按场景选表式族，支持两行表头与合并单元格 | `report_artifacts.py`（`_form_titles` / `_form_template` / `_tunnel_form_row`） |
| 测项 → 表号映射（D2→D3→D4→D1 顺序，避免"深层水平位移"被 D1 抢走） | `scenarios/tunnel.json` 的 `report.form_rules` |
| 表式来源登记 + 未覆盖测项披露 | 同上 `report.basis` / `unsupported_form_metrics` |

映射结果（实测）：拱顶沉降/净空收敛/地表沉降 → **表D1**；深层水平位移 → **表D2**；
锚杆轴力/支撑轴力 → **表D3**；围岩压力/钢架应力/衬砌应力/孔隙水压力 → **表D4**。

## 4. 还有两个明确的缺口（不掩饰）

1. **现场巡查表（附录 C）暂不出表**。载荷里没有巡视记录结构，按既有规则"未提供巡视记录不生成
   巡视表，且不得写成巡视正常"。要做需要先定义巡视数据结构（部位/内容/结果/处理建议）。
2. **附录 D 未涵盖的测项不出附表**：地下水位、裂缝宽度、爆破振动速度。这三项在规范附录 D 中
   确实没有表式，我没有自造表格，也没有挪用基坑表 E/F；数值仍在冻结明细与超限测点清单里，
   并在画像 `unsupported_form_note` 中披露，等你的项目模板。
