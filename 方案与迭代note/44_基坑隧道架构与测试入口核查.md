## 架构连接

工作台 `/workbench` → 授权工程及参数 → 上传/解析 → `/api/runs` → 场景准备与Python确定性计算 → 冻结事实 → Supervisor查证 → 报告编写 → 确定性及语义审计 → 工程师复核。

公开工程类型仅基坑与隧道，分别映射 `foundation-pit`、`tunnel-monitoring`。旧盾构绑定兼容到隧道入口，工法等作为工程参数；测试用适配器不作为生产场景。每类均登记六个解析、归一化、计算、严格性、渲染及校验处理器；规则由Python执行，TypeScript负责编排与契约。

| 层次 | 代码位置 | 职责 |
|---|---|---|
| 展示 | `src/app/workbench/` | 工程、条件、上传、运行、报告、复核 |
| API与编排 | `src/app/api/`、`src/server/runs.ts`、`src/server/preparation/` | 权限、场景准备、事实冻结、运行记录 |
| 专业适配 | `engineering-adapters/foundation-pit/`、`tunnel-monitoring/` | 参数、判据、模板、专业处理器与检索配置 |

| Agent | `src/server/agents/` | 查证、编报、独立审计及意见修订 |
| 证据与存储 | `src/server/evidence/`、`storage/` | 独立规范范围、工程隔离、运行及文件存储 |
| 验证 | `tests/`、`tools/test/`、`final_test/` | 回归、测试入口与发布样例 |

## 发现及修复

原 `final_test/latest/` 的冻结快照缺少新增单位、位置/稳定性字段及工程条件透传；日明细hash随字段增加变化，导致旧复现脚本直接比较失败。原始观测、累计、速率、等级及判据核对未改变。历史报告正文还按旧载荷描述缺少工程条件，不应直接用于当前载荷。

完整保留历史目录，单独生成当前模板样例，不复用旧模型正文。默认验证脚本改指新包，新增手工可算的累计/速率与工程条件断言；保持完整快照、文件hash、单元格、Markdown和报告审计核对，不通过忽略字段或跳过失败来宣称通过。
