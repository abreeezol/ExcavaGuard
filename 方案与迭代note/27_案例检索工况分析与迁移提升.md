# 案例检索、工况分析与进一步迁移提升

日期：2026-11-04。基坑适配器升级至2.1.0。

## 本轮实现

两项能力保留为通用Skill，避免每种工程复制上传、检索、时间/位置关联程序。专业测项语义由适配器form_rules提供；supporting_context策略定义位置字段、同日策略和候选预算。日后若需要新检索算法或时间策略，须开发并测试支持的策略，不能仅改一个未支持的配置值。

- `/api/project-context`提供当前获授权项目的列表、JSON/文件上传、JSON模板下载和启停。案例支持结构化JSON、UTF-8 TXT/Markdown，工况和巡视使用结构化JSON；记录支持时间、区段、测点、文本、记录人和可选结构化断言。
- 独立私有目录`var/project-context/<project_id>`保存资料，绑定项目和适配器，保留内容指纹、上传人和时间；不写规范库，不覆盖规则。文件写入为原子操作并加项目锁，重复内容去重。最多200份存档、同时启用50份，启用内容总预算控制在运行快照上限之内。
- 案例Skill按显式测项或场景关键词检索，返回匹配词、来源和片段；不是语义向量检索，不把词汇重合当作同工况或因果成立。
- 工况Skill按报告窗口、同日和明确同区段/同测点关联；不同区段排除，位置缺失或同测点区段矛盾列为待核。周期报告使用每日冻结观测，而非只关联最严重的一天。
- 相同时间、位置、断言键出现不同断言值时，保留冲突供人工确认。未提供结构化断言的自然语言矛盾不保证自动识别。
- 日报可不提供辅助资料；资料读取不可靠时明确披露未引用，继续可靠监测计算。规范检索和语义审查仍保留原有故障阻断，不以辅助能力为由放宽审计。
- 本次辅助来源、检索与关联结果写入`project.supporting_context`，并建立Agent context_snapshot；报告和语义审计使用同一冻结版本。案例ID不冒充规范evidence_ids，辅助事实使用绑定占位符，停用不改变历史报告。
- Supervisor在有相应资料时留下两个Skill调用轨迹；报告含资料名称、案例候选、关联、待核和冲突披露。独立Python文件审计重建相同内容；补充资料不修改任何原监测数值或风险。

当前八个业务Skill均有实现，但两项新增能力仅在上述输入和策略范围内完成验证；不是任意格式、多模态或自动因果推理。

## 仍应改进的迁移任务

| 优先级 | 缺口 | 建议验收标准 |
|---|---|---|
| P0 | 真实隧道专业包尚未制作，只有生产禁用的接口验证包 | 选择一种工法、代表性测项，核实公式/适用条件/规范，跑通真实输入格式、独立RAG、日报与审计 |
| P0 | 专业规则缺少系统性的工程师金标准评价 | 明确已核实规则范围，建立已知答案、边界、缺参和冲突样例；工程确认与软件测试分开记录 |
| P1 | 案例目前按关键词检索，不能证明工程条件相似 | 增加工法、土层、地下水、支护/结构、阶段等经确认标签；有标注集后评估召回与排序，再决定是否增加向量检索 |
| P1 | 工况目前为同日关联，复杂时序和自然语言冲突尚弱 | 增加项目时区、作业起止区间、空间映射和受控专业策略；区分时间关联、工程假设和已核实原因 |
| P1 | 此入口尚不支持PDF/图片/CSV工况自动抽取 | 先做可搜索PDF、CSV字段映射及抽取预览；保留页码/行号与原文件哈希；扫描件OCR质量不足时拒绝 |
| P1 | 适配器历史执行包和远端RAG内容版本未完整归档 | 保留不可变适配器发布包、知识库目录/内容版本、升级确认和可重放样例，避免只能依赖当前工作树 |
| P1 | 自动时间窗口推荐还未实现 | 从解析结果展示日报/周报/月报可选窗口，披露覆盖和缺测，不靠用户手工填写日期 |
| P2 | 单服务文件/SQLite持久化不适合多个独立实例 | 统一部署持久卷或迁移受授权的共享服务，测试跨实例一致性与项目隔离 |
| P2 | 检索缓存、全局排队和费用指标缺少系统评测 | 按工程/适配器/知识库版本缓存，约束并发与预算，统计P50/P95耗时、错误率、引用命中和人工退回原因 |

不建议把剩余差异全部塞入提示词，也不建议复制三Agent。通用机制持续复用；专业内容、策略和必要专业程序由适配器承接，再以第二个真实场景证明迁移。

## 使用

刷新工作台，在“案例、工况与巡视资料”上传并启用，随后新建运行；旧运行不自动吸收后来上传的资料。管理员若遇适配器版本升级提示，在工程条件处确认保存一次再生成新报告。未修改用户真实账号或工程配置，未推送。
