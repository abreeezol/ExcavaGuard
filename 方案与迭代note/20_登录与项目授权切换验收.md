# 登录、项目授权与切换

更新：2026-10-27。此功能在 `7247ff3` 基线上实现，按用户要求随本次提交发布到上游 `main`。真实账号目录、凭据和本机验收截图不入库。

## 当前工作流

独立账号登录 → 选择获授权工程 → 自动加载该工程的监测文件、阈值文件、补充规范和运行历史 → 上传、报告生成、复核和下载均绑定当前工程。

切换工程会卸载原工作台并清空尚未提交的输入和已打开结果，重新加载所选工程资产。不会把工程A正在填写的文件带入工程B。上传或分析期间禁用本页切换；其他标签页切换后，旧页面携带不同的 `X-Excavaguard-Project` 会被服务端拒绝，请刷新后重选。未授权工程不出现在列表，手工修改请求也不能获取权限。

监测数据以“已上传文件”列表加载，工程师选择文件运行；不会自动合并多份文件。补充规范沿用原有项目SQLite库，上传时解析和建索引，后续报告复用索引检索；普通工程切换不重新入库。同项目成员共享历史，原运行创建人保持不变，实际复核人独立记录。

## 首次启用独立账号

在仓库根目录使用Node 24运行，若WSL没有Node，可将 `.tools/node/bin/node` 替代下方的 `node`。

```bash
node --env-file-if-exists=.env.local tools/access/manage.mjs init --username admin --name 管理员
```

初始账号凭据仅保存在 `var/access/credentials/admin.txt`，权限0600，不回显密码、不进入Git。管理员在本机读取文件后登录工作台；登录后先选择工程。初始化保留默认工程UUID、既有文件与报告；若此前用共享模式创建过多个工程，原 `local-operator` 成员关系转交首个管理员，不复制或改写业务数据。

未执行 `init` 时保持原共享密码/localhost访问配置，可先使用页面的“创建并切换”体验多工程；该兼容模式代表同一个操作者，不能区分不同工程师。独立账号初始化后，原共享密码不再用于登录。系统不会替用户自动创建真实账号。

账号初始化和授权变更按下一请求读取，无需重启；安装本次代码后需要先重启工作台服务。

## 创建工程与添加成员

系统管理员登录后，在页面填写工程名称，点击“创建并切换”。新工程只授权创建者，其他成员需要显式分配。项目管理员角色本身不授予创建全局新工程的权限。

```bash
node --env-file-if-exists=.env.local tools/access/manage.mjs add-user --username engineer1 --name 工程师甲
node --env-file-if-exists=.env.local tools/access/manage.mjs add-user --username reviewer1 --name 复核工程师
node --env-file-if-exists=.env.local tools/access/manage.mjs list
```

`list` 显示工程UUID、用户及成员关系，隐藏密码哈希和会话密钥。用页面或列表中的工程UUID授权：

```bash
node --env-file-if-exists=.env.local tools/access/manage.mjs grant --username engineer1 --project 工程UUID --role engineer
node --env-file-if-exists=.env.local tools/access/manage.mjs grant --username reviewer1 --project 工程UUID --role reviewer
```

将“工程UUID”替换为实际值。新增成员没有默认工程授权，不能看到其他工程。成员在各自浏览器登录；已登录页面点击“刷新授权”即可更新列表。

| 项目角色 | 查看文件、规范和历史、下载已审计草稿 | 上传、生成或续跑、管理补充规范 | 提交接受、退回或拒绝 |
| --- | --- | --- | --- |
| admin 项目管理员 | 是 | 是 | 是 |
| reviewer 复核工程师 | 是 | 是 | 是 |
| engineer 工程师 | 是 | 是 | 否 |
| viewer 只读成员 | 是 | 否 | 否 |

系统管理员与工程角色分开：系统管理员可以创建工程，但读取某工程仍需成员授权。

撤销工程访问或停用账号：

```bash
node --env-file-if-exists=.env.local tools/access/manage.mjs revoke --username engineer1 --project 工程UUID
node --env-file-if-exists=.env.local tools/access/manage.mjs disable-user --username engineer1
```

改密使用环境变量输入，避免明文密码写入命令行历史：

```bash
read -r -s -p '新密码（至少12字符）: ' EXCAVAGUARD_NEW_PASSWORD
export EXCAVAGUARD_NEW_PASSWORD
node --env-file-if-exists=.env.local tools/access/manage.mjs set-password --username engineer1
unset EXCAVAGUARD_NEW_PASSWORD
```

改密、停用会使旧会话失效；撤销成员资格后旧会话也不能继续访问该工程。初始凭据文件仅记录创建时密码，改密后不会自动同步它。

## 存储与接口

- 授权目录：`EXCAVAGUARD_ACCESS_FILE`，默认 `var/access/directory.json`。包含账号scrypt密码哈希、项目、成员和随机会话签名材料；原子写入与文件锁防止覆盖。目录不可由Web接口直接下载。
- 会话：签名HttpOnly Cookie，8小时有效，SameSite=Strict；HTTPS时带Secure。选择工程须通过 `POST /api/projects/select` 核验成员关系，不能使用请求正文中的UUID自动切换。
- `GET/POST/DELETE /api/session`：状态、账号/密码登录、退出。
- `GET /api/projects`：仅返回登录用户获授权的有效工程。
- `POST /api/projects`：系统管理员创建工程；`POST /api/projects/select`：选择工程。
- 监测文件、阈值文件、运行和产物继续使用原local/Supabase Provider；其API在访问存储前核验当前项目和角色。补充规范仍在 `var/project-standards/<project_id>/standards.sqlite3`，不写公共RAG。
- `EXCAVAGUARD_PROJECT_ID` / `EXCAVAGUARD_PROJECT_NAME` 用于首次初始化默认工程，不再作为独立账号模式的固定项目选择器。改显示名称不迁移历史数据。

即使业务存储使用Supabase，授权目录和补充规范SQLite仍需挂载持久卷并备份；保留原工程UUID才能继续读取原资产。本实现面向单服务实例，并非Supabase Auth / 企业SSO；不同部署实例不能各自维护相互冲突的目录。跨设备访问还需部署可达的HTTPS服务，现有localhost启动不会自动对外开放。
