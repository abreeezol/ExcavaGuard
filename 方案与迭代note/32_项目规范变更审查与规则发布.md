# 项目规范变更审查与规则发布

日期：2026-11-04。未推送上游；保留原三Agent与工程适配器架构。

## 解决什么问题

原来上传的项目规范只进入独立RAG检索库。新增规则审查流程，使其中可执行的要求能够被提取、审计、集中确认并用于新报告判级；没有成功结构化的要求继续作为检索证据，并明确披露。

## 使用路径

1. 登录并选择项目，在工作台“项目补充规范”上传可搜索PDF、TXT或Markdown。
2. 在“规范变更审查与确认”点击该文件的“分析规则变更”。
3. 查看摘要、原文摘录、规范名称/版本/条款、适用条件、程序校验及审查问题。
4. 可选择已有运行进行只读影响试算。试算基于该运行冻结事实，最多显示100条等级变化，不覆盖历史报告，也不等同完整重新计算。
5. 管理员或复核工程师逐条接受/不采用，必要时修改阈值、比较关系、测点或已有条件值，并说明修改理由。填写集中确认说明后发布；发布前会再次程序校验及独立模型审计。
6. 或填写意见“退回修改”，再点击“按意见重新分析”。Supervisor、报告、审计三个角色重新处理，累计最多两轮；达到上限后人工修改候选或拒绝提案。
7. 新建日报、周报、月报或自定义区间报告时，程序自动加载当前项目已发布且适用的规则。停用变更单或来源文件后，仅影响后续新运行。

工程师可上传和发起分析；发布、退回、拒绝及停用规则需要管理员/复核工程师角色。本地单人模式保留原有管理员使用方式。

## 三Agent与程序职责

| 角色 | 本任务职责 |
|---|---|
| Supervisor | 规划审查重点，识别需比对的条件与要求 |
| 报告Agent | 生成候选结构化规则、关键差异说明及未决清单 |
| 审计Agent | 对照原文独立检查数值、单位、条件与冲突；发布前复核工程师修改 |
| 确定性程序 | 原文绑定、结构/单位/数值检查、权限与版本校验、规则执行、周期汇总及事实冻结 |
| 工程师 | 逐条确认采用范围与修改，保留最终决定 |

这是上传时触发的另一类三角色任务，不增加第四个常驻Agent，不替换日常报告的三Agent链。

## 当前可执行范围及边界

- 复用当前适配器的测项与参数契约，基坑与隧道均已接通。
- 当前执行器支持毫米变形测项的正向累计量、正向变化速率，单位分别为mm和mm/d，比较关系为达到/超过，等级必须对应原文中的关注/预警/报警/危险报警，条件为工程参数等值匹配，可限定测点。
- 数值必须能对应当前文件的逐字原文摘录；支持的单位和条件必须完整。格式校验不等同语义正确，仍需独立模型审计和工程师确认。
- 建议区间、比例/公式、频率、其他单位、反向变形和无法表达的条件不自动转为固定限值。作为待核要求披露；不能声称上传的整本规范均已成为可执行规则。
- 补充规则与原判据**并行核查，只增加提醒、不降低原等级**，不覆盖原控制值或解除其他弃权。更低的提醒阈值可与原控制值共存；正式预警发布与处置仍由工程师决定。
- 已匹配测项但缺少必要条件/有效数值时，新增规则核查结果待核；低等级原结果标记未知，原有预警及以上结果不降级。
- 已知失效、效力待核或范围不符的公共规范不能通过重新上传绕过规则发布门禁。新项目专用文件仍需工程师核对来源、效力及适用性，不宣称系统已完成全网效力核验。
- 全部可索引切片输入单次审查；目前切片正文上限90000字符，候选规则最多40条。超过上限明确要求分章节上传，不能把截断/抽样描述成全文审查。扫描件需先OCR，未索引页会进入待核清单。
- 运行输入不变时不会自动重写旧报告。项目配置/适配器摘要变化后，已确认规则暂停采用并提示重新核验。
- 仍是同步处理、单实例本地持久化；尚非后台任务队列或多实例数据库事务。

## 追溯与存储

- 来源文件与RAG：沿用 `EXCAVAGUARD_PROJECT_STANDARDS_ROOT/<project_id>` 的项目独立SQLite库，不写公共规范库。
- 规则变更：`EXCAVAGUARD_STANDARD_CHANGES_ROOT/<project_id>`，默认 `var/standard-changes`，包含版本历史及带SHA-256的head指针，项目级锁和CAS防止并发覆盖。需挂载持久卷并备份。
- 冻结事实：`project.rule_change_snapshot`，记录规则版本、项目、专业能力摘要、配置摘要、已接受规则、原文/页码/文件哈希、确认人及缺口。
- 条目：`project_rule_checks`记录命中、未触发、不适用、条件缺失等；`checks`保存阈值、值、单位和规范名称/条款。
- 报告说明同步保留采用要求和待核事项，避免只有后台快照留痕。

接口：`GET/POST /api/project-standards/changes`，操作为analyze、preview、publish、return、reject、disable；写入操作绑定expected_version。客户端不能指定工程师身份或其他工程，均由当前登录和授权项目确定。

## 测试

`tests/standard-changes.test.ts`：受控三角色的流程/失败注入、退回及两轮上限、人工编辑、并发版本、项目隔离、配置/文档停用、多日统计、只读试算、基坑和隧道真实Python日报生成及文件核验。

可选真实模型测试：

```bash
EXCAVAGUARD_TEST_RULE_CHANGES_LLM=1 node --env-file-if-exists=.env.local node_modules/vitest/vitest.mjs run tests/standard-changes.test.ts -t '真实模型完成'
```

真实模型测试使用临时项目文件和明确标为SIMULATED的人工要求，经三角色分析及发布前独立审计，测试程序模拟工程师确认；不代表真实工程规范或真实工程师专业签认。首轮发现模型接口要求JSON提示词、审计误解“补充提醒”与“覆盖控制值”，已修正提示和执行契约，保留阻断机制。
