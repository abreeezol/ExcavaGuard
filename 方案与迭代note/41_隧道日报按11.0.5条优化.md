# 41 · 隧道日报按 GB 50911-2013 第 11.0.5 条优化
> 迁移说明（2026-11-09）：本文描述的隧道日报渲染实现（附录 C/D 表式、11.0.5 八节结构）**未随本次合并迁入**，仍保留在分支 `feat/tunnel-scenario-gb50911`（PR #10）。本次合并只迁入引擎侧判定能力与判据库，待上游报告层稳定后再移植。

> 本轮只改 `render-daily-report` 技能（渲染侧）与载荷可选字段，不动引擎判定口径，
> 不动基坑 service-v5，不动前端与服务端。

## 一、条文原文（OCR 已核对，第 11.0.5 条第 1 款）

> 监测报告可分为日报、警情快报、阶段性报告和总结报告。监测报告应采用文字、表格、
> 图形、照片等形式，表达直观、明确。监测报告宜包括下列内容：
> **1 日报**
> 1）工程施工概况；
> 2）现场巡查信息：巡查照片、记录等；
> 3）监测项目日报表：仪器型号、监测日期、观测时间、天气情况、监测项目的累计变化值、
> 变化速率值、控制值、监测点平面位置图等，可采用本规范附录 D 的样式；
> 4）监测数据、现场巡查信息的分析与说明；
> 5）结论与建议。

对照发现三处硬缺口：

| 条文要求 | 改造前状态 |
|---|---|
| 第 2 项 现场巡查信息 | 只有一句“巡视记录未提供；未生成附表G”，**没有巡查章节、没有附录 C 表** |
| 第 3 项 表头要素 | 表头是空的“＿＿＿＿”，**仪器型号/出厂编号/检定日期/天气不会注入**，也没有“观测时间”的如实披露 |
| 第 3 项 监测点平面位置图 | **完全没有** |
| 第 4 项 “与现场巡查信息”的分析 | 分析只基于监测数据，**未声明巡查缺失的边界** |
| 第 5 项 结论与建议 | 结论混在“简要分析”里，没有独立成节；断面结论未进入日报 |

## 二、改造后的日报结构（隧道）

| 节 | 内容 | 数据来源 |
|---|---|---|
| 一 | 工程施工概况 | `project` + `conditions`（监测等级/工法/区域/断面形式/围岩）+ 埋深/跨度/直径/Ls + 规范依据 |
| 二 | 现场巡查信息 | `patrol`；按工法选附录 C 表；无记录只披露缺失 |
| 三 | 监测项目日报表 | 附录 D 表式说明 + 本期用表 + 未纳入表式的测项 + **表头九项要素逐项核对** |
| 四 | 监测数据、现场巡查信息的分析与说明 | 综合判定/风险分布/分项统计/断面综合判定/周期统计/弃权统计/巡查边界声明 |
| 五 | 结论与建议 | 综合等级、报警清单、未知条数、断面结论、建议 |
| 六 | 待复核事项 | 弃权、缺口、数据质量（附列，审计必需） |
| 七 | 规范核对依据（RAG） | 附列，审计必需 |
| 八 | 签署 | 附列，签认必需 |

工作簿顺序：封面 → 附表C（仅当有巡查记录）→ 附表D1~D4 → 监测点平面位置图 → 超限测点清单 → 规范证据。

基坑仍是 service-v5 五节结构，代码走独立分支，回归已确认不动。

## 三、改了什么

### 1. 正文分节（`report_adapter.py`）
- 拆成 `_jikeng_cover_blocks()` / `_tunnel_cover_blocks()`，由 `project.scenario_id` 或
  `EXCAVAGUARD_SCENARIO` 分派；待复核/规范依据/签署三节抽为共用函数，避免两套文案漂移。
- 分项统计改为按附表展示名分组（`表D1 水平位移、竖向位移`），不再只认 A~F。
- `build_report()` 新增 `sections.patrol`、`sections.section_judgment`，并在 `trace` 输出
  `patrol_record_count`、`section_count`。

### 2. 现场巡查（新增，附录 C）
- `tunnel_appendix_forms.PATROL_FORMS` 按规范登记 C.0.1/C.0.2/C.0.3 的**全部应巡查内容**
  （C.0.3 共 21 项，分施工工况/支护结构/周边环境/监测设施）。
- `patrol_form_for_method()`：明挖/盖挖→C.0.1，盾构→C.0.2，矿山法→C.0.3，**工法未知返回 None，不出表**。
- `match_patrol_records()`：归一化后整串比对，对不上就按原文列入“其他”保留，不丢记录、不做语义猜测。
- 渲染：规范列出但未记录的项写“未填写”（红底样式），并注明“规范应巡查内容，本期未记录”；
  无记录时不生成附表 C，正文第二节与第六节均写明“不得判定现场巡查正常”。

### 3. 表头要素注入
- 附录 D 表头改为占位符模板，注入：工程名称、报表编号（草稿）、天气、本次监测时间、
  仪器型号、仪器出厂编号、检定日期。
- 缺值保留“＿＿＿＿”（不使用“—”，表头留白与“无此项”含义不同），并写入待复核：
  “表头已保留空位，需现场填写后方可归档”。

### 4. 监测点平面位置图（新增工作表）
- 输出测点清单：序号/点号/名称/测项/断面或里程/坐标 X/Y。
- 坐标来自测点台账 `points_meta` 的 `x`/`y`（可选），已在 `build_daily_report_input()` 透传
  `mileage`/`x`/`y`；未提供显示“—”并披露数量。
- 表内明确：正式平面图由项目提供，本表不是测量成果图、不用于放样。

### 5. 契约
- `daily_report_input.schema.json` 新增可选顶层 `patrol`（method/time/weather/inspector/records/photos），
  其余字段与必填项不变；`items` 新增可选 `mileage`/`x`/`y`。

### 6. 画像
- `tunnel.json` 的 `report` 段登记 `daily_report_structure`（五节 + 三附列）、`patrol_forms`、
  `patrol_form_rule`、`point_layout`、`header_elements`，供渲染器与前端读取，不在代码里重复假设。

## 四、边界（刻意不做的事）

1. **不编造巡查结果**：没有 `patrol.records` 就不出附表 C，绝不生成“全部正常”的空表。
2. **“未填写”不等于“正常”**：巡查表与正文都这样写，且进入待复核。
3. **不补造坐标**：没有坐标只列清单，不按点号画点位。
4. **不猜巡查表**：工法未知时不出表。
5. **不动判定**：巡查结果不参与五级分级，风险等级仍来自冻结判据。
6. **照片只统计数量**：`patrol.photos` 只记录文件名/数量，系统不嵌入图片、不判断图片内容。

## 六、仍待输入

1. **巡查照片本体**：现在只统计数量并提示补附，若要嵌入图片需约定存储路径与版式位置。
2. **观测时刻**：载荷时间戳目前多到日（`00:00:00`），表头会如实写“需现场补填”；数据源带时刻即可自动填。
3. **正式平面位置图**：需要项目提供 CAD/PDF，或提供测点坐标由项目出图；系统只出清单。
4. **RAG 语料**：按约定由你提供切片，接入后第七节才能出现真实条文。
