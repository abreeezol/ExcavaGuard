# 工程师意见重编与日报信息补齐（2026-11-03）

本轮基于34aa849及原有本地修改，接通工程师退回意见到实际AI重编及独立审查，并补齐单位、工程条件、日内极值的报告可见性。只生成供工程师复核的草稿，不改冻结风险，不自动签发。尚未提交或推送。

## 行为与使用

1. 复核人完成风险评价后填写退回原因，提交“退回修改”。
2. 点击“载入输入并按退回意见重编”。前端恢复原输入并开启AI报告；修正必要的数据/条件后点击运行。
3. 服务端按当前项目读取父版本，在新运行创建时冻结原因、逐项评价、父修订/草稿引用及原稿正文。此后续跑使用冻结意见，不重新读取可变历史。
4. 报告逐项返回具体回应；正文、Excel及附表Markdown展示意见回应及前后对照。遗漏回应、越界事实、错误引用不能交付。
5. 文件审计及独立语义审查通过后重新交工程师接受、退回或拒绝。未解决事项直接转人工；不能自动接受或靠修改风险文字消除异议。未解决子版本换新输入重跑时继续继承原意见。

模板模式仅记录原意见，明确尚未自动修订并阻断完整通过；不以模板重渲染冒充模型吸收意见。

## 信息传递与可读性

- 引擎新增向后兼容的`items.unit`，归一化观测单位经过阶段二进入冻结载荷；旧载荷保留，未给单位不猜。
- 实际计算context中的安全等级、支护形式、开挖深度进入project，避免已用于计算却在报告中丢失。
- “日内统计核对”分别展示日末、最小、最大值及各自单位、样本数、采样窗口和已知极值时刻；来源统计不改变日末风险，也不代替逐条原采样审查。
- 原CSV可带JSON文本来源信息，协作合并复用标准化器解析，避免dict(文本)异常。
- 模型仅接收需要的日内统计标量，不发送每条来源行号数组，完整来源仍保留在冻结数据和审计文件。
- 对已提供条件误称缺失、计数误写成类别、附表跨类引用增加确定性校验；对日内变化过程的推断须有实际序列依据。

## 审查边界与兼容

新增可选快照及反馈回应字段，旧运行不改写。反馈保存在现有运行JSON记录中，无需新增Supabase表/列；原上游协作迁移仍需按部署环境核实。项目权限、revision CAS、下载审计和风险逐项评价门禁保留。

独立审查会发现真实正文问题，也可能遇到外部模型超时或预算耗尽。此时不能直接接受，保留阻断稿与原因；不承诺每次调用均能自动修订通过。最多两轮自动修订及原调用/时间预算保持不变。

本轮不实现工况/巡视文件接入、因果判断或独立日内阈值判级，不将模拟验证当作真实工程师评价。原测试数据和正式账号未修改。
